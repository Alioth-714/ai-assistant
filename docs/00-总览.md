# ai-assistant 项目总览

> 状态：已定稿 | 最后更新：2026-01-15 | 关联：全部设计文档

## 一、项目定位

本地优先的个人 AI 助手，一个底座承载多个角色（开发辅助/通用/垂直领域），每个角色内含主协调者+专业子 Agent 群协作。

- **内部中文名**：小明同学
- **工程名**：ai-assistant（GitHub 全小写连字符）
- **本地目录**：`AIAssistant/`（可选）
- **前端**：Tauri v1 + 纯 HTML+CSS+JS
- **核心语言**：Rust

## 三、核心四层架构

工具层（Layer 4）是支撑设施，不算入核心层数。

| 层级 | 模型 | 职责 | 生命周期 |
|------|------|------|---------|
| **Layer 0 路由** | 3B (Qwen2.5-3B) | 意图分类：开发/通用/垂直 → 选择角色 | 常驻 |
| **Layer 1 角色** | 配置/YAML | 工具集、权限、知识域、记忆隔离、prompt | 常驻（缓存池） |
| **Layer 2 主协调者** | 7B (Qwen2.5-7B) | 唯一跟用户对话，拆任务、派 Agent、汇总、决策轻重活 | **常驻**（7B 加载慢，显存够用） |
| **Layer 3 子 Agent** | 3B轻活/7B重活/云端 | 专业执行，独立上下文，返回结构化结果 | 按需唤醒 |
| **Layer 4 工具层** | — | 文件操作、grep、git CLI、网络请求等支撑 | 随调随用 |

**数据流向**：
用户输入 → Layer 0 路由（意图分类）
→ Layer 1 角色加载（工具/知识/记忆）
→ Layer 2 主协调者（拆任务、派发）
→ Layer 3 子 Agent 执行（读工作区、调工具）
→ Layer 2 汇总结果 → 用户

## 四、关键约束（硬限制）

| 约束 | 值 |
|------|------|
| Token 硬上限 | 3B=4K / 7B=8K |
| 写操作 | 必须走权限网关 L2 confirm |
| 数据出境 | 默认不出本机；云端只接脱敏描述 |
| 子 Agent 嵌套 | 禁止（只能调工具，需额外信息返回主协调者再派） |
| 并发写互斥 | 同一文件同一时刻只允许一个 Agent 写（文件锁 JSON） |
| 网络访问 | 常见文档站（docs.*/wiki.*/github.com）默认允许，其他首次询问 |
| 配置格式 | JSON（缩进 2 空格） |
| 角色定义格式 | YAML |
| 知识文件格式 | 结构化 JSON |
| 日志 | tracing crate，输出到 `AI_ASSISTANT_DATA/logs/` |
| 显存/并发调度 | 见 `design/27-性能优化.md`（权威：3B 路由常驻 GPU、7B 主协调 offload、子 Agent 3B 并发 2） |
| 模型纯净 | 模型一律为干净基底（不带人设）；人设存配置层（agent.md / 角色 YAML prompt），换模型/换路径人设不变 |

## 五、数据目录结构

> 数据根：`AI_ASSISTANT_DATA` 环境变量优先；未设置时 debug 用 `{仓库目录}/data/`，release Windows 用 `%LOCALAPPDATA%\ai-assistant-data`，其他平台用 `$HOME/.local/share/ai-assistant/data`。数据目录与安装目录分离。

AI_ASSISTANT_DATA/
├── config/ JSON 配置文件（app.json 等）
├── knowledge/ 知识库
│ ├── shared/ 公共知识（所有角色可读不可改）
│ ├── dev/ 开发角色知识
│ ├── general/ 通用角色知识
│ └── {custom_role}/ 自定义角色知识
├── memory/ 记忆
│ ├── shared/ 公共记忆（所有角色可读不可改）
│ ├── dev/ 开发角色记忆
│ ├── general/ 通用角色记忆
│ └── {custom_role}/ 自定义角色记忆
├── workspace/ 任务工作区（{task_id}/，任务完成/取消时销毁）
├── backups/ 文件级备份（写前备份，回滚用）
├── cache/ 缓存
│ ├── external/ 外部链接抓取缓存
│ └── models.json 模型列表缓存
└── logs/ 运行日志（tracing 输出）

## 六、开发阶段（摘要）

详见 `roadmap/15-开发路线.md`

| 阶段 | 范围 | 退出标准 |
|------|------|---------|
| 阶段 0 | 复用验证期：Cline + Ollama 跑通 agent.md，记「别扭点」，不自研代码 | 角色行为符合预期、工具/记忆可用、别扭点清单 |
| 阶段 1 | 核心骨架 MVP：工程骨架 + 路由 3B + 主协调者 7B（单轮）+ 工具/网关 + 前端 | `cargo build` 通过、能分类意图并回复、L2 拦截与写前备份生效 |
| 阶段 2 | 协作与记忆：子 Agent + 工作区 + 文件锁并发 + 记忆/知识库 + 失败回滚 | 能派发任务并回收结果、2 子 Agent 并发不冲突、诱导失败自动回滚 |
| 阶段 3 | 扩展与优化：工具/角色扩展 + 向量检索 + 链接自主学习 + 网络域名策略 + 性能调度 + 测试覆盖 | 新增工具无需改核心、知识可注入召回、外网受控、测试全绿 |
| 阶段 4 | 安全与生态：云端兜底 + 多模态 + 敏感记忆加密 + 插件 + 自动更新/回滚 + 发布 | 渗透无高危、加密不可明文读、更新可回滚、可对外分发 |
