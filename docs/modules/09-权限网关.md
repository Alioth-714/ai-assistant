# 09 权限网关

> 状态：已定稿 | 最后更新：2026-01-15 | 对应决策：6, 17, 26（权威定义见 `design/03-权限模型.md`、`design/04-数据边界.md`、`design/22-安全模型.md`）

## 职责

所有工具调用必须经过网关，网关负责：

1. 判定操作级别（L0/L1/L2/L3）
2. 按「先级别、后横切策略」顺序检查（网络域名策略、文件写保护）
3. 执行确认流程
4. 备份文件（写操作，决策 6）
5. 记录审计日志

> **强化扩展（2026-10-22）**：网关是 **Tool Guard 子层**（`modules/10-工具层.md` §十三，决策 32）的前置校验主体——参数校验 / 路径守卫 / 权限 / 备份 / 循环检测由网关承接，写后自检与结果规范化由 Tool Guard 补在工具执行之后。

## 流程

```
工具调用
  ↓
[网关入口]
  ├─ 判定级别（L0/L1/L2/L3，见 03-权限模型.md）
  ├─ 检查横切策略（网络域名、文件写保护，见 04/22）
  ├─ 备份文件（如涉及写操作，见 21-更新与回滚.md）
  ├─ 执行确认（L2 弹窗 / L3 二次警告）
  └─ 放行 / 拒绝
  ↓
[执行工具]
  ↓
[审计日志]
```

## 审计日志

每条记录包含：

```json
{
  "timestamp": "2026-01-15T10:30:00+08:00",
  "agent": "refactorer",
  "tool": "write_file",
  "level": "L2",
  "target": "src/main.rs",
  "params_summary": "修改 main 函数",
  "result": "success",
  "backup_path": "backups/20260115-1030/src_main_rs.bak"
}
```

日志统一输出到 `AI_ASSISTANT_DATA/logs/audit.log`（权限/网络/备份/回滚事件同文件，JSON Lines，轮转见 `22-安全模型.md` §7.1）。

## 备份机制（决策 6）

```
写文件前
  → 检查目标文件是否存在
  → 存在 → 复制到 backups/{批次时间戳}/{路径编码}.bak（结构见 21-更新与回滚.md §3）
  → 执行写操作
  → 失败 → 从备份恢复
  → 成功 → 按 21 的保留策略（30 天/1GB）统一清理，任务完成不立即删
```

## 网络权限（决策 17）

域名策略（权威见 `03-权限模型.md` §4.1 与 `22-安全模型.md` §4.4）：

| 域名类型 | 策略 |
|---------|------|
| docs.* / wiki.* / github.com | 默认允许（可配置开关） |
| 其他域名 | 首次访问询问 |
| 用户「始终允许」 | 进白名单，不再询问 |
| 用户「拒绝」 | 进拒绝列表 |

会话内同域名只问一次，24 小时内不重复问。

## 文件访问白名单

默认允许：项目目录（AI_ASSISTANT_DATA 及用户指定的工作根目录）
默认禁止：

- `~/.ssh/`
- `~/.aws/`
- `~/.config/` 下密钥文件
- 环境变量中的密钥
- `.env` / `.key` / `.pem` 文件
- 路径遍历防护：解析后必须落在允许基目录内（决策 27，见 `04-数据边界.md`）

## 人工介入（Interrupt）

写操作（L2）触发确认弹窗，用户可选：

- 允许
- 允许本次任务内同类操作
- 拒绝
- 编辑参数后再执行

L3 危险操作需二次警告确认（见 `03-权限模型.md` §3.4）。
