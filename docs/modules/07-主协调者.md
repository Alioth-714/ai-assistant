# 07 - 主协调者

> 状态：已定稿 | 最后更新：2026-01-15 | 关联：02-架构设计.md、03-权限模型.md、04-数据边界.md、06-路由层.md、08-记忆与知识.md、10-工具层.md、roadmap/18-本地云端边界方案.md

## 一、概述

主协调者（Layer 2）是 ai-assistant 四层架构的**核心调度层**，负责接收路由层请求、拆解任务、派发子 Agent、汇总结果，并维护整个对话周期的上下文状态。

**核心职责**：
- 任务拆解：将用户请求分解为可独立执行的子任务
- 子 Agent 派发：选择合适的子 Agent（3B），分配工具和工作区
- 结果汇总：收集子 Agent 输出，合并为最终回复
- 上下文管理：维护对话上下文，超限时外移数据+摘要压缩
- 失败协调：处理子 Agent 失败，触发重试/回滚

**设计决策**：使用 **7B 模型**（qwen25-7b）**常驻 VRAM**，确保调度质量和响应速度。

> **阶段 2 实测补充（2026-10-22）**：本地 7B/7B Q4 的**多步工具链（读到内容→下一步写入）实测 100% 失败**（写占位符/丢内容）。因此主协调者的「多步编排」**不再交给模型自持串联**，改为：**代码显式拼接工具结果，模型每次只做单步决策**；本地不足的难点单步走**云端兜底**。详见 `roadmap/18-本地云端边界方案.md`。

## 二、职责边界

| 职责 | 说明 | 不负责 |
|------|------|--------|
| 任务拆解 | 分析请求，生成子任务 DAG | 不执行具体文件操作 |
| 子 Agent 管理 | 唤醒、派发、监控、回收 | 不嵌套派发子 Agent |
| 上下文维护 | Token 计数、外移、压缩 | 不持久化到磁盘（由记忆层负责） |
| 工具调用决策 | 决定何时调用工具 | 不直接执行工具（派发给子 Agent 或自身调用轻量工具） |
| 用户交互 | 流式输出、权限确认请求 | 不处理原始输入（路由层负责） |
| 失败处理 | 重试协调、回滚触发 | 不执行底层回滚（工具层负责） |

| 复杂度 | 判断依据 | 处理方式 |

## 四、子 Agent 管理

### 4.1 生命周期
创建 → 唤醒（加载模型）→ 派发任务 → 执行 → 完成/失败 → 释放（模型卸载）
纯文本
- **唤醒**：3B 子 Agent 按需加载，第 1 个进 GPU、第 2 个走 CPU（显存调度见 `27-性能优化.md`）
- **并发上限**：3B 子 Agent 最多 2 个同时运行；7B 子 Agent 走 CPU/云端
- **超限请求**：排队（最多 30s）→ 降级 CPU / 云端 / 串行化
- **释放**：任务完成后卸载模型，释放显存

### 4.2 派发机制

- 主协调者通过**工作区 JSON** 传递数据（不共享内存）
- 子 Agent 读取 `workspace/{task_id}/context.json` 获取任务
- 子 Agent 写入 `workspace/{task_id}/tool_outputs/` 存放结果
- 主协调者轮询或监听完成信号

### 4.3 禁止嵌套（决策 4）

- 子 Agent **不可**再派发子 Agent
- 若子任务需进一步拆解，返回主协调者处理
- 防止递归失控

## 五、上下文管理

### 5.1 Token 硬上限

| 参数 | 值 | 说明 |
|------|------|------|
| Token 上限 | 8K | 含系统提示+对话历史+工具结果 |
| 预警线 | 70% (5.6K) | 开始外移非关键数据 |
| 强制压缩线 | 90% (7.2K) | 触发摘要压缩 |

### 5.2 外移策略

当 Token 使用达 70% 时，将非关键数据替换为指针：

| 数据类型 | 外移方式 | 指针格式 |
|---------|---------|---------|
| 工具调用结果 | 存 `workspace/{task_id}/tool_outputs/{id}.json` | `[TOOL_OUTPUT:{id}]` |
| 早期对话轮次 | 生成摘要，原文替换 | `[SUMMARY:{task_id}:{round}]` |
| 知识库检索结果 | 只保留引用 ID | `[KNOWLEDGE:{id}]` |
| 文件内容 | 存工作区，保留文件路径 | `[FILE:{path}]` |

### 5.3 摘要压缩

当 Token 使用达 90% 时：

1. 标记关键决策点（用户指令、Agent 决策、写操作）
2. 对非关键轮次用 3B 快速摘要
3. 替换原文，保留关键轮次完整
4. 压缩后 Token 数应下降 >30%

### 5.4 角色切换与上下文缓存（决策 10）

- 角色切换时，**不销毁**主协调者实例（7B 常驻）
- 当前角色上下文序列化存入**角色缓存池**
- 新角色上下文从缓存池加载（若存在）
- 缓存池位置：`AI_ASSISTANT_DATA/cache/role_contexts/`
json
{
"role": "dev",
"context_summary": "...",
"key_decisions": ["使用 tokio", "修改 main.rs"],
"token_count": 3200,
"saved_at": "2026-01-15T10:30:00+08:00"
}

### 6.2 重试策略

| 错误类型 | 重试次数 | 退避 |
|---------|---------|------|
| 模型推理超时 | 2 | 固定 2s |
| 文件锁冲突 | 5 | 固定 500ms |
| 网络超时 | 3 | 指数退避 1s/2s/4s |
| 配置错误 | 0 | 不重试 |

### 6.3 回滚协调

- 主协调者记录任务中所有写操作
- 失败时按**逆序**触发回滚
- 调用工具层 `restore_backup` 接口
- 回滚结果报告用户

## 七、性能要求

| 指标 | 目标 | 说明 |
|------|------|------|
| 首 token 延迟 | < 2s | 7B 模型冷启动/首次生成 |
| 任务拆解时间 | < 3s | 含 7B 推理 |
| 显存占用 | ≤ ~4GB（GPU 部分） | Q4_K_M，GPU 分层 offload（见 27 §2.3） |
| 常驻状态 | 内存常驻 + GPU 分层 | 角色切换复用（决策 10） |
| 并发子 Agent | 最大 2 | 受显存限制 |

## 九、与其他层的交互

### 9.1 ← 路由层（Layer 0）

- 接收：意图标签、置信度、建议角色、预处理元数据
- 可覆盖路由建议（如意图为 task 但过于简单，直接回答）

### 9.2 → 角色层（Layer 1）

- 请求角色配置（YAML）
- 获取工具集绑定、权限上限
- 切换角色时保存/加载上下文缓存

### 9.3 → 子 Agent（Layer 3）

- 派发任务、传递工作区数据
- 监控状态、收集结果
- 回收资源

### 9.4 → 工具层（Layer 4）

- 调用工具（主协调者自身可执行轻量工具如 `read_file`）
- 请求权限检查
- 触发备份/回滚

## 十、Planner 子层（编排增强，2026-10-22 新增）

**背景**：阶段 2 实测确认本地 7B/7B **多步工具链不可靠**（模型扛不住跨步状态传递：写占位符/丢内容，见 `roadmap/18` §二）。因此主协调者的「任务拆解/派发」升级为 **Planner 子层**：**计划先行 + 单步决策**，模型永远只做单步决策、绝不跨步自持（决策 31）。

**职责**：接收请求 → 产出结构化 plan（步骤数组）→ 逐单步推进（每步 = 一次工具调用或一次单步推理）→ 结果回注 → 汇总 / 失败处理。

**核心机制**：

1. **计划先行**：先产出完整 plan 再执行，不做「边想边做」
2. **单步决策**：模型每步只输出「下一步调哪个工具、参数是什么」；工具结果由**代码显式拼接**注入下一步（A 方案核心，见 `roadmap/18`）
3. **步数上限 + 调用去重**：硬卡循环（多步是循环高危区）
4. **每步最小上下文**：只注入当前步所需输入；超长工具结果截断/摘要（外移指针，决策 9）
5. **失败策略**：按类型重试 → 回滚 → 报告/询问用户（决策 3）

**plan 结构（示例）**：

```json
{
  "task_id": "t_001",
  "goal": "把 demo.txt 的按钮名改掉并总结",
  "steps": [
    {"id": 1, "type": "read",     "params": {"path": "workspace/demo.txt"}, "expect": "content"},
    {"id": 2, "type": "write",    "params": {"path": "workspace/demo.txt", "content": "<代码注入 read 结果+改动>"}, "expect": "ok"},
    {"id": 3, "type": "summarize","params": {"ref": "step1"}, "expect": "text"}
  ],
  "status": "pending"
}
```

**实现范围（决策 31，已拍板）**：

- 第一版只做 **P1 模板状态机**（硬编码任务模板：read→write→backup、read→append 等），覆盖常见任务、全本地快
- 开放式任务（未命中模板）→ 阶段 3 接**云端拆 plan**（A+C 的 cloud 部分，见 `roadmap/18`），本地按 plan 逐单步执行
- 单步决策默认用**大脑 `qwen25-7b`（heavy 档）**（2026-10-22 拍板：运行时只留 7B 一个大脑，不来回切）；纯推理单步（总结/问答）用同一大脑

**与 Tool Guard 的接口**：Planner 提出步骤 → Tool Guard 校验后执行 → 结果回注（见 `10-工具层.md` §十三）。

**配置**（`config/app.json` 新增占位）：

```json
"planner": {
  "enabled": true,
  "max_steps": 12,
  "max_retries_per_step": 2,
  "loop_dedup": true,
  "template_dir": "templates/"
}
```
