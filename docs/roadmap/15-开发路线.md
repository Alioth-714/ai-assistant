# 15 - 开发路线

> 状态：已定稿 | 最后更新：2026-01-15 | 关联：00-总览.md、01-项目定位.md、02-架构设计.md、30-总结与路线图.md

## 一、概述

本文档定义 ai-assistant 工程的**五阶段开发路线（阶段 0-4）**，明确每个阶段的**范围、交付物、退出标准**。详细架构决策见各 `docs/design/` 文件。

**总目标**：构建本地多 Agent 协作系统，支持路由→角色→主协调者→子 Agent 四层协作，纯本地推理（Ollama），前端 Tauri 封装。

**阶段总览**：

| 阶段 | 主题 | 一句话 |
|------|------|--------|
| 0 | 复用验证期 | Cline + Ollama 跑通 agent.md，不写自研代码，记「别扭点」 |
| 1 | 核心骨架（MVP） | 自研最小闭环：路由 3B + 主协调者 8B + 子 Agent + 工具/网关 + Tauri 前端 |
| 2 | 协作与记忆 | 多 Agent 协作、文件锁并发、记忆/知识库、失败回滚 |
| 3 | 扩展与优化 | 工具/角色扩展、向量检索、网络、性能调度、测试覆盖 |
| 4 | 安全与生态 | 注入防护、敏感记忆加密、插件、自动更新、发布 |

## 二、阶段 0：复用验证期

**目标**：不写自研代码，用成熟载体（Cline + Ollama + `agent.md`）先把「角色 + 工具 + 记忆」的工作方式跑通，记下别扭点，作为阶段 1 自研最小核心的需求输入。

**范围**：
- 在官方 Cline 中配置 Ollama（**开发工具 = `qwen3:8b`**，原生工具调用可靠；运行时大脑 heavy 档 = `qwen25-7b`，见 `ops/12-模型部署.md` §模型池与档位），注入 `agent.md` 作为开发角色系统提示
- 验证：角色行为符合预期、文件读写工具调用、记忆读写、失败提示
- 产出「别扭点清单」：哪些交互繁琐、工具缺失、模型力不从心

**阶段 0 实测记录（B+D 策略依据）**：

- 通用 7B（qwen25-7b）做 Cline agent 任务：**循环重复调用同一工具**（104 次重复读同一文件）、**文件写到一半截断**、每回合 20s~2.5min；coder 7B 工具调用格式不匹配（文本 JSON 而非原生 `tool_calls`）→ 判定 7B 级通用/coder 模型**不适合 Cline 开发期 agent 编排**，**开发工具**改用 `qwen3:8b`（原生工具调用可靠；默认开 thinking，见 `models/README.md`）。**注意：这是"开发工具"场景的判定，不是运行时大脑**——大脑（heavy 档）仍为 `qwen25-7b`，其运行时表现已按 `roadmap/17` §阶段 2 用 test.sh 实测：**单步工具可靠、0 循环，但多步工具链必挂、改文件有截断波动**（详见 `roadmap/18` §二）
- 结论：**不给每个角色配独立模型**，先最小集（light + heavy + cloud）跑通，按别扭点数据驱动特化（见 `ops/12-模型部署.md` §模型池与档位）
- 阶段 2 大脑实测补充（test.sh）：qwen25-7b 与 qwen3:8b 均原生 `tool_calls`、单步可靠、0 循环；**多步工具链（读→写）两模型 100% 失败**；qwen3:8b 工具执行比 qwen25-7b 稳。→ 采 **A+C 折中**（代码编排 + 云端兜底），边界见 `roadmap/18-本地云端边界方案.md`

**复用工具对比**（选型参考，来自总纲）：

| 工具 | 特点 | 适用 |
|------|------|------|
| Cline | VSCode 插件，工具链完整（读写/终端/浏览器） | **首选日常载体** |
| Aider | 终端原生，git 集成为核心卖点 | git 驱动开发 |
| OpenCode | 开源、支持多模型/provider | 备选 |
| Goose / OpenHands | 通用 agent 框架 | 备选 |

> 反模式：**不要一上来就写完整 agent 框架**。先用成熟载体跑起来，最小自研核心从阶段 1 开始。

**退出标准**：

| 标准 | 验证方式 |
|------|---------|
| 角色行为符合预期 | agent.md 注入后，多轮对话表现稳定 |
| 工具调用/记忆读写正常 | 让 Cline 读文件、改文件、写记忆 |
| 别扭点清单产出 | 记录 ≥10 条，作为阶段 1 需求输入 |

## 三、阶段 1：核心骨架（MVP）

**目标**：跑通四层架构最小闭环，验证本地模型推理 + 工具调用。基于阶段 0 的别扭点清单确定优先级。

### 3.1 范围

| 模块 | 内容 |
|------|------|
| 路由层（3B） | 意图识别、分发逻辑、Token 硬上限 4K |
| 主协调者（8B） | 任务拆解、子 Agent 派发、结果汇总 |
| 子 Agent（3B） | 单文件读写、grep、写前备份 |
| 工具层 | read_file / write_file / grep 实现，权限网关 L0-L3 |
| 前端 | 基础对话界面（Tauri v1），流式输出 |
| 数据层 | 工作区 JSON、配置 JSON、目录结构初始化 |

> 模型按 B+D（见 `ops/12-模型部署.md` §模型池与档位）：路由 = light（3B 常驻）、主协调者 = heavy 档（`qwen25-7b`，运行时大脑）；**开发期 Cline 工具 = `qwen3:8b`**（非运行时档位）。MVP 只跑最小集，不为每个角色配独立模型。

### 3.2 交付物

- [ ] `src/router/` — 路由模块（调用 Ollama 3B）
- [ ] `src/coordinator/` — 主协调者模块（8B 常驻）
- [ ] `src/agents/` — 子 Agent 模块（按需唤醒）
- [ ] `src/tools/` — 内置工具（read/write/grep）
- [ ] `src/gateway/` — 权限网关
- [ ] `src-tauri/` — Tauri 项目骨架
- [ ] `config/app.json` 模板
- [ ] `AI_ASSISTANT_DATA/` 目录自动创建（数据根：环境变量 > debug 仓库/data/ > release 用户数据目录）

### 3.3 退出标准

| 标准 | 验证方式 |
|------|---------|
| 路由正确分类用户输入 | 手动测试 10 条不同意图输入 |
| 主协调者能拆解简单任务 | 输入"重构 main.rs"能生成子任务 |
| 子 Agent 完成文件读写 | 自动修改文件并写前备份 |
| 前端可发送消息并显示流式输出 | 手动验证 |
| 权限网关拦截 L2 操作 | 尝试写文件触发确认 |

## 四、阶段 2：协作与记忆

**目标**：多 Agent 协作流畅化，记忆/知识库可用，失败处理完善。

### 4.1 范围

| 模块 | 内容 |
|------|------|
| 多 Agent 协作 | 广播/认领机制、工作区 JSON 共享、文件锁 |
| 记忆系统 | 分层记忆（`shared/` + `{role}/`）、JSON 存储 |
| 知识库 | 三层结构、关键词检索、手动添加 |
| 失败处理 | 按类型重试→检查原因→回滚已改→报告用户 |
| 权限网关完善 | L0-L3 拦截、前端确认弹窗 |
| 前端增强 | 任务进度展示、权限弹窗、设置页面 |

### 4.2 交付物

- [ ] 工作区管理模块（`src/workspace/`）
- [ ] 记忆模块（`src/memory/`）
- [ ] 知识库模块（`src/knowledge/`）
- [ ] 失败处理与回滚（`src/error.rs` 完善）
- [ ] 前端任务进度组件
- [ ] 前端权限确认弹窗
- [ ] 前端设置页面（配置编辑、模型管理）

### 4.3 退出标准

| 标准 | 验证方式 |
|------|---------|
| 2 个子 Agent 并发不冲突 | 同时派发 2 个写任务，文件锁生效 |
| 角色切换记忆隔离 | 切换角色后原角色记忆不泄露 |
| 知识检索可用 | 添加知识条目后能检索到 |
| 诱导失败后自动回滚 | 模拟写失败，验证备份恢复 |
| L2 弹窗确认 | 前端弹出确认对话框 |

## 五、阶段 3：扩展与优化

**目标**：扩展机制、性能优化、网络能力、测试覆盖。

### 5.1 范围

| 模块 | 内容 |
|------|------|
| 工具扩展 | 新增工具注册机制（Rust trait） |
| 角色扩展 | 自定义角色 YAML 加载 |
| 知识检索升级 | 向量检索（embedding 字段） |
| 网络能力 | 链接抓取、域名策略、缓存 |
| 性能优化 | 显存调度（见 27）、并发上限、异步备份、上下文分段 |
| 测试覆盖 | 集成测试、E2E 测试 |

### 5.2 交付物

- [ ] 工具注册表（`src/tools/registry.rs`）
- [ ] 自定义角色加载器
- [ ] 向量检索模块（本地向量库）
- [ ] 外部链接抓取器（`src/tools/web_fetch.rs`）
- [ ] 性能监控（`logs/metrics.jsonl`）
- [ ] 集成测试套件（`tests/`）
- [ ] 缓存管理模块（`src/cache/`）

### 5.3 退出标准

| 标准 | 验证方式 |
|------|---------|
| 新增工具无需改核心代码 | 添加新工具只需实现 trait + 注册 |
| 自定义角色可用 | 创建 YAML 文件，切换成功 |
| 语义搜索可用 | 向量检索返回相关结果 |
| 外网访问受控 | 陌生域名触发询问 |
| 目标硬件流畅运行 | i5-10400F + RTX 2070 上无卡顿（按 27 §2.3 调度） |
| 核心测试通过率 100% | `cargo test` 全部绿 |

## 六、阶段 4：安全与生态

**目标**：安全加固、加密、插件生态、正式发布。

### 6.1 范围

| 模块 | 内容 |
|------|------|
| 安全加固 | Prompt 注入防护、写操作互斥、审计日志完善 |
| 敏感记忆加密 | AES-256-GCM，密钥 Argon2id 派生自用户口令 |
| 插件生态 | Tauri 插件机制、第三方扩展签名验证 |
| 自动更新 | 增量更新、版本检测、回滚 |
| 文档完善 | 用户手册、开发指南、API 文档 |
| 正式发布 | GitHub Release、安装包签名、离线部署包 |

### 6.2 交付物

- [ ] 加密模块（`src/crypto/`）
- [ ] 插件加载器（`src/plugins/`）
- [ ] 自动更新器（Tauri updater 配置）
- [ ] 用户手册（`docs/user-guide/`）
- [ ] 开发指南（`docs/dev-guide/`）
- [ ] GitHub Actions CI/CD
- [ ] 安装包签名 + 离线部署包（见 `26-部署与分发.md` §4.4）

### 6.3 退出标准

| 标准 | 验证方式 |
|------|---------|
| 渗透测试无高危漏洞 | 专项安全测试通过 |
| 加密字段不可明文读取 | 直接打开文件验证 |
| 第三方插件可加载 | 安装示例插件并运行 |
| 更新失败可自动回滚 | 模拟更新中断，验证回滚 |
| 用户可自助部署 | 按文档步骤成功安装 |
| 可对外分发 | GitHub Release 发布 |
