## 一、背景

阶段 0-4（`roadmap/17`）跑通后进入当前开发。本轮两件事：

1. **冒烟验证现有 src-tauri 实现**（前置，先确认当前代码可用）
2. **补两块稳定工作流骨架**（解决「不够智能/不稳定」）：
   - **Planner 子层**（见 `07-主协调者.md` §十）：计划先行 + 单步决策，解决本地多步工具链不可靠
   - **Tool Guard 子层**（见 `10-工具层.md` §十三）：确定性工具调用守卫，防越界/乱改/循环/截断

> 原则：**先做到能用**；后续升级硬件/换模型时，这两层**模型无关**、架构不动（符合 B+D 与 `roadmap/18` A+C 折中）。

## 三、步骤

### 第 1 步：阶段 4 冒烟验证（前置）

- `cargo build`（src-tauri）
- **CDP 冒烟清单**（均需无 JS 报错）：
  - Provider 增删改 / 测试 / 默认对话模型保存
  - 外部发送 + 用量卡
  - 本地失败选择器
  - 外部失败本地回退
  - 导出闸门 modal
  - 消息操作按钮
- 修复问题并跑**全量检查套件**：
  - `cargo fmt`（根 + src-tauri）
  - `clippy`（根 + src-tauri）
  - `cargo test`
  - `node --check`
  - HTML/CSS 平衡
  - `git diff --check`

### 第 2 步：阶段 5A — 数据目录指针与迁移（文本框方案，零新插件）

- `data.rs::root()` 解析顺序：
  1. `AI_ASSISTANT_DATA` 环境变量
  2. 指针文件 `%APPDATA%\ai-assistant\data-location.json`
  3. 调试默认 `app_root/data`
  4. `%LOCALAPPDATA%\ai-assistant-data`
- 新 Tauri 命令 `set_data_root(path)`：
  - 校验目标路径
  - `ensure_layout`（初始化目标目录结构）
  - 复制当前默认数据目录全部内容并**逐字节校验**
  - 写指针文件
  - 返回 `restartRequired`
- 前端「数据」tab：目标路径文本框 + 「迁移并重启」按钮 + 说明（仅迁移当前默认目录，**不引入 fs/dialog 插件**）

### 第 3 步：阶段 5B — 首次启动引导

- 后端：沿用 `settings.onboardingCompleted`（已有）
- 前端：首次启动（`onboardingCompleted=false`）弹 3 步轻量 modal：
  1. 欢迎
  2. `check_environment` 检测本地模型
  3. 外部 Provider 快速配置或跳过
- 完成/跳过 → 写回 `onboardingCompleted=true`

### 第 4 步：阶段 5C — 生产日志 + 打包脚本

- `logging.rs` 改 `rolling::daily` + 保留份数；仅 debug 输出 console；保证 `WorkerGuard` 生命周期
- 只产出**打包文档 + 脚本**（如 `scripts/bundle.ps1` 说明 `tauri build` 步骤），本轮**不实际生成安装包**

### 收尾

- 全量检查套件通过后，更新 docs/（如模块文档）记录新命令与设置项
- 给出一份阶段小结
