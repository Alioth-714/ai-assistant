# 20 · 外部模型智能化（大版本规划）

> 状态：规划中，不在当前迭代范围。当前只支持 OpenAI `chat/completions` 协议的单轮问答。

## 一、暂不支持的供应商协议（后续大版本适配）

| 供应商 / 协议 | 现状 | 需要做的事 |
|---|---|---|
| OpenAI `responses`（GPT 新接口） | 未实现 | 增加 `openai-responses` 协议适配层：请求体、事件流解析、工具调用格式 |
| Anthropic `messages`（Claude） | 未实现 | 增加 `anthropic-messages` 协议：`system` 独立字段、`content` 数组、`thinking.budget_tokens` |
| Google Gemini 原生 API | 未实现 | 独立协议族（`generateContent`），与 OpenAI 兼容层差异较大 |
| 百度千帆 / 讯飞星火 / 腾讯混元等 | 部分有 OpenAI 兼容入口，未验证 | 按预设逐个实测后加入 `config/providers.json` |

预设里只放**已验证或高置信度**的 OpenAI 兼容地址；其余按本表挂起，避免用户选到就报错。

## 二、推理等级（reasoning effort）

- 现状：`config/providers.json` 的模型条目支持 `reasoning: { param, levels }`，但**运行时未透传**
- 待做：
  1. `ModelSetting` 增加 `reasoningLevels` / `defaultReasoningLevel`
  2. 请求时按协议映射：OpenAI 兼容 → `reasoning_effort`；Anthropic → `thinking.budget_tokens`
  3. 聊天框下拉展示等级，每个模型记住上次选择
  4. 不支持的模型不显示等级入口

## 三、工具调用与执行能力

- 现状：外部模型只做单轮对话，没有工具调用，无法达到 Cline / Claude Code 的“读代码→改代码→跑测试”闭环
- 待做：
  1. 支持 OpenAI `tools` / `tool_calls`，本地执行工具（受权限网关约束）
  2. 「云端顾问 + 本地执行」：本地 7B 出计划与工具调用，云端给方案与代码片段
  3. 接入 MCP / CLI 执行器（把 Cline、Claude Code 当外部工具调用）

## 四、上下文与压缩

- 现状：压缩参数尚未实现，仅确定默认值
- 待做：
  1. 按 profile 生效的压缩策略：本地 6000 / 1800 / 4000，云端 16000 / 6000 / 16384
  2. 每个模型可配置上下文长度与压缩阈值
  3. 摘要触发与保留窗口的可观测日志

## 五、其他待办

- 删除保护（默认模型被引用时阻止删除）

## 六、OpenCode Console 多协议接入（大版本再做）

实测与文档 `https://opencode.ai/v2/docs/console/api/inference` 对照后记录：

**1. 按模型家族分路径**

| 家族 | 路径 |
|---|---|
| OpenAI Chat Completions | `/inference/openai/v1/chat/completions` |
| OpenAI Responses | `/inference/openai/v1/responses` |
| Anthropic Messages | `/inference/anthropic/v1/messages` |
| Gemini | `/inference/google/v1beta/models/<model>:generateContent` |

**2. 我们当前的局限**

- 只实现 `openai-chat`，GPT（responses）、Claude/Qwen（messages）、Gemini 三类模型必然失败
- 模型清单未解析家族归属，界面无法提示"该模型需要其他协议"

**3. 已打通的 Go 通道（实测）**

- 对话：`https://opencode.ai/inference/go/v1/chat/completions`
- 清单：`https://opencode.ai/inference/v1/models`
- 必须 `stream: true`
- 必须带请求头 `x-opencode-session`
- 文档未提 `/inference/go/v1` 路径，需在大版本时确认是否长期有效

**4. 其他要点**

- 免费档模型在非 OpenCode 客户端会被拒（403 / FreeUsageLimitError）
- 响应 `usage` 带 `cost` 与 `opencode.billing_source`（free/balance/go/go-plus/byok），可用于展示单次花费

**5. 后续工作**：模型家族标注 → 逐家族协议适配 → 错误与计费透明化 → Go 路径归一。
