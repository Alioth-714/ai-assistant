# 03 - 权限模型

> 状态：已定稿 | 最后更新：2026-01-15 | 关联：02-架构设计.md、modules/09-权限网关.md、design/05-失败处理.md

## 一、概述

权限系统采用**分级 + 横切策略**的双维度模型：

- **权限级别（L0-L3）**：定义操作的风险等级，决定是否需要用户确认
- **横切策略**：网络访问、文件写保护等跨级别的规则，独立于权限级别执行

两者**正交**，按顺序执行：先检查权限级别是否需要确认，再检查横切策略（如域名白名单）。

## 二、权限分级

| 级别 | 名称 | 说明 | 典型操作 | 用户确认 |
|------|------|------|---------|---------|
| **L0** | 只读·安全 | 不修改任何数据，不访问外部网络 | `read_file`、`list_dir`、`grep`、`read_memory` | 无需确认 |
| **L1** | 只读·外部 | 读取外部资源（网络、git clone 等），不修改本地数据 | `web_fetch`、网络文档读取、`git_status`/`git_diff`/`git_log` | 无需确认（但受网络策略约束） |
| **L2** | 写操作·本地 | 修改本地文件、执行命令、提交代码 | `write_file`、`edit_file`、`git_commit`、`run_command` | **必须确认**（弹出确认框） |
| **L3** | 危险操作 | 系统级变更、批量删除、权限提升 | 修改系统配置、删除整个目录、`git push --force`、安装软件 | **必须确认 + 二次警告** |

### L1 与网络策略的关系（已修正）

**L1 是权限级别，网络访问是横切策略，两者正交。**

- L1 表示"该操作只读取外部数据，不修改本地数据"——权限级别上不升级
- 但网络访问本身受**域名策略**约束（见第四节）
- 执行顺序：先判断 L1 无需用户确认 → 再检查域名策略 → 若域名不在白名单则**询问用户是否允许访问**
- 因此 L1 操作可能仍会弹出询问（针对陌生域名），这不是权限升级，而是网络策略拦截

## 三、权限网关拦截流程

所有工具调用必须经过权限网关（`src/gateway/permission.rs`）：

## 四、横切策略

### 4.1 网络访问策略（决策 17）

| 域名类型 | 处理方式 |
|---------|---------|
| `docs.*`、`wiki.*`、`github.com` | 默认允许（可配置开关显式控制） |
| 其他域名 | 首次访问询问用户："是否允许访问 {domain}？" |
| 用户选择"始终允许" | 加入会话白名单 |
| 用户选择"拒绝" | 记录到拒绝列表，本次会话不再询问 |
| 询问频率 | 同一域名 24 小时内不重复询问（可配置 `reask_after_hours`） |

配置项（`app.json`）：
json
{
"network": {
"allowed_domains": ["docs.", "wiki.", "github.com"],
"ask_on_first_access": true,
"session_cache": true,
"reask_after_hours": 24
}
}

### 4.2 文件写保护

- **写前备份**：所有 L2/L3 写操作执行前，自动备份目标文件到 `AI_ASSISTANT_DATA/backups/`（决策 6，详见 `21-更新与回滚.md`）
- **并发互斥**：同一文件同一时刻只允许一个 Agent 写（文件锁 JSON，见 `05-失败处理.md` §2）
- **敏感路径保护**：`AI_ASSISTANT_DATA/memory/` 下的文件禁止子 Agent 直接修改（只能主协调者写入）

### 4.3 外部内容安全（Prompt 注入防护）

- 抓取到的网页/文档内容**只作为数据**，不作为指令执行
- 子 Agent 上下文隔离：外部内容注入时标记来源，主协调者过滤后注入
- 禁止外部内容包含 `system:`、`ignore previous` 等指令关键词（检测并警告）

## 五、审计日志

所有权限相关事件记录到 `AI_ASSISTANT_DATA/logs/audit.log`：

| 事件 | 记录内容 |
|------|---------|
| 权限拒绝 | 时间戳、工具、级别、原因 |
| 用户确认 | 时间戳、工具、用户选择（允许/拒绝） |
| 网络访问 | 时间戳、URL、域名、是否首次询问、用户选择 |
| 写前备份 | 时间戳、目标文件、备份路径 |
| 文件锁冲突 | 时间戳、文件、请求者、持有者 |

**日志轮转与磁盘上限**（决策补充）：
- 默认轮转策略：单文件超过 10MB 时轮转，保留最近 5 个
- 磁盘上限：审计日志总大小不超过 500MB（超过时删除最旧文件）
- 配合整体磁盘约束：AI_ASSISTANT_DATA 总大小 < 20GB

## 六、角色权限配置

角色 YAML 中声明该角色允许的最高权限级别：
yaml
src/roles/builtin/dev.yaml
role:
name: dev
max_permission: L2 # 开发角色最高允许 L2（写操作需确认）
allowed_tools:
•
read_file
•
write_file
•
edit_file
•
git_commit
# 不包含 L3 危险操作
纯文本
主协调者加载角色时，从 YAML 读取 `max_permission`，所有派发给子 Agent 的任务受此上限约束。
