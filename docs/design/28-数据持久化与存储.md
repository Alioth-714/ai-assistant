# 28 - 数据持久化与存储

> 状态：已定稿 | 最后更新：2026-01-15 | 关联：02-架构设计.md、04-数据边界.md、08-记忆与知识.md、19-数据迁移.md、21-更新与回滚.md、27-性能优化.md

## 一、概述

ai-assistant 作为本地多 Agent 协作系统，所有数据（配置、记忆、知识库、任务工作区、日志、缓存）均存储在用户机器上。本文档定义数据的**存储格式、目录结构、读写策略、生命周期管理**和**安全约束**。

**核心原则**：
- 数据以**结构化 JSON** 为主格式（可读、可编辑、可版本控制）
- 写操作前必须**备份原文件**（文件级备份，决策 6）
- 敏感数据（阶段 4+）支持加密存储
- 所有数据路径受**数据边界**约束（见 `04-数据边界.md`）
- 用户可随时手动查看/编辑数据文件（纯文字版本偏好）

## 二、数据目录结构

### 2.1 根目录

默认位置：`AI_ASSISTANT_DATA` 环境变量优先；未设置时，debug 使用 `{仓库目录}/data/`，release Windows 使用 `%LOCALAPPDATA%\ai-assistant-data`，其他平台使用 `$HOME/.local/share/ai-assistant/data`。数据目录与安装目录分离，避免卸载程序时误删用户数据。
AI_ASSISTANT_DATA/
├── config/
│ ├── app.json # 主配置文件
│ ├── secrets.json # API Key 等敏感配置（阶段 3+ 加密）
│ └── models.json # 模型注册表（cache/models.json 软链或复制）
├── knowledge/
│ ├── shared/ # 所有角色可读不可改
│ │ ├── general/ # 通用知识
│ │ └── dev/ # 开发相关知识
│ ├── general/ # 公共角色知识（可读可写）
│ └── {custom_role}/ # 自定义角色知识（每个角色独立目录）
├── memory/
│ ├── shared/ # 公共记忆（所有角色可读不可改）
│ │ └── facts.json # 共享事实
│ ├── {role_name}/ # 角色独立记忆
│ │ ├── conversations.jsonl # 对话摘要/关键决策
│ │ └── preferences.json # 角色偏好
│ └── user/ # 用户级记忆（跨角色）
│ └── profile.json # 用户信息
├── workspace/
│ └── {task_id}/ # 任务工作区（JSON 结构化数据）
│ ├── task.json # 任务元数据
│ ├── context.json # 任务上下文指针
│ ├── tool_outputs/ # 工具调用结果
│ └── .lock.json # 文件锁
├── backups/ # 写前备份
│ └── {yyyy-mm-dd}/
│ └── {file_path_hash}/
│ └── {timestamp}_original.json
├── cache/
│ ├── external/ # 外部链接抓取缓存
│ │ └── {url_hash}.json
│ ├── role_contexts/ # 角色上下文缓存（决策 10，角色切换时保存/恢复）
│ ├── model_responses/ # 模型响应缓存（阶段 3+）
│ └── models.json # 模型元数据缓存
├── logs/
│ ├── app.log # 应用主日志（tracing 输出）
│ ├── audit.log # 审计日志
│ └── metrics.jsonl # 性能指标（循环写入）
└── roles/ # 用户自定义角色 YAML
└── {role_name}.yaml
纯文本
### 2.2 路径约定

| 约定 | 说明 |
|------|------|
| 路径分隔符 | 统一使用 `/`（Rust `std::path` 处理，前端显示用 `/`） |
| 文件命名 | 小写字母 + 连字符（`my-file.json`），无空格 |
| 编码 | UTF-8 without BOM |
| 行尾 | LF（\n） |
| JSON 缩进 | 2 空格 |
| JSON 字段排序 | 按字母序（便于 diff 和版本控制） |
| 注释 | 使用 `_comment` 字段（JSON 不支持原生注释） |

## 四、工作区数据

### 4.1 任务工作区

每个任务创建独立目录 `workspace/{task_id}/`，任务完成或取消后销毁，孤儿 24h 清理。

**`task.json`**：

"updated_at": "2026-01-15T10:05:00+08:00",
"coordinator": "qwen25-7b",
"sub_agents": [
{
"id": "sub_001",
"model": "qwen25-3b",
"status": "completed",
"tools_used": ["read_file", "write_file"]
}
],
"workspace_files": [
"src/main.rs",
"src/lib.rs"
]
}
纯文本
**`context.json`**：
json
{
"pointers": {
"original_file": "src/main.rs",
"backup_path": "backups/2026-01-15/abc123_10:00:00_original.json",
"tool_output_dir": "tool_outputs/"
},
"shared_data": {
"file_contents": {},
"decisions": []

纯文本
### 4.2 文件锁

`workspace/{task_id}/.lock.json`：
json
{
"locked_by": "sub_001",
"locked_files": ["src/main.rs"],
"acquired_at": "2026-01-15T10:03:00+08:00",
"expires_at": "2026-01-15T10:03:30+08:00"
}
纯文本
- 锁超时 30s 自动释放
- 读写锁分离：读操作不阻塞其他读

## 五、记忆存储

### 5.1 分层结构

| 层 | 路径 | 读写权限 |
|---|------|---------|
| 公共记忆 | `memory/shared/facts.json` | 所有角色可读，不可改（仅主协调者可追加） |
| 角色独立记忆 | `memory/{role}/conversations.jsonl` | 该角色读写，其他角色不可见 |
| 用户级记忆 | `memory/user/profile.json` | 跨角色，用户可编辑 |

### 5.2 格式

**`memory/shared/facts.json`**：
json
{
"schema_version": "1.0",
"facts": [
{
"id": "fact_001",
"content": "用户偏好 Rust 语言",
"source": "agent",
"confidence": 0.95,
"created_at": "2026-01-15T10:00:00+08:00"
}
]
}
纯文本
**`memory/{role}/conversations.jsonl`**（每行一个 JSON 对象）：
json
{"timestamp":"2026-01-15T10:00:00+08:00","type":"summary","content":"用户要求重构 main.rs，使用异步模式"}
{"timestamp":"2026-01-15T10:05:00+08:00","type":"decision","content":"选择 tokio 作为异步运行时"}
纯文本
**`memory/user/profile.json`**：
json
{
"display_name": "用户",
"preferences": {
"language": "zh-CN",
"theme": "dark",
"verbosity": "concise"
},
"system_info": {
"os": "Windows 10",
"cpu": "i5-10400F",
"gpu": "RTX 2070",
"ram_gb": 16
}
}
纯文本
### 5.3 敏感记忆加密（阶段 4+）

- 使用 AES-256-GCM 加密
- 密钥派生自用户口令（Argon2id，决策 28）
- 加密字段标记 `"encrypted": true`

## 六、知识库存储

### 6.1 三层结构
knowledge/
├── shared/ # 所有角色可读不可改
│ ├── general/ # 通用知识（如编程概念）
│ └── dev/ # 开发知识（如 Rust 文档）
├── general/ # 公共角色知识（可读可写）
└── {custom_role}/ # 自定义角色知识
纯文本
### 6.2 知识文件格式

每个知识条目为独立 JSON 文件：
json
{
"schema_version": "1.0",
"id": "kb_rust_async_001",
"title": "Rust 异步编程基础",
"content": "异步编程使用 async/await 语法...",
"source": "manual",
"tags": ["rust", "async", "tokio"],
"created_at": "2026-01-15T10:00:00+08:00",
"updated_at": null,
"embedding": null
}
纯文本
### 6.3 检索索引

- 阶段 1-2：关键词检索（基于标签和标题全文匹配）
- 阶段 3+：向量检索（embedding 字段存储向量，本地向量库如 `sled` 或 `sqlite-vec`）

### 6.4 混合维护

| source 值 | 说明 | 可编辑方 |
|-----------|------|---------|
| `manual` | 用户手动添加 | 用户 |
| `agent` | Agent 自动积累 | 主协调者 |
| `hybrid` | 用户编辑 + Agent 补充 | 用户/主协调者 |

## 七、缓存管理

### 7.1 外部链接缓存

`cache/external/{url_hash}.json`：
json
{
"url": "https://example.com/article",
"fetched_at": "2026-01-15T10:00:00+08:00",
"expires_at": "2026-01-22T10:00:00+08:00",
"content_hash": "sha256:abc123...",
"summary": "文章摘要...",
"full_text": "抓取的全文内容..."
}
纯文本
- 默认过期时间：7 天
- 同一域名 1min 内不超过 5 次请求
- 可配置过期时间

### 7.2 模型响应缓存（阶段 3+）

`cache/model_responses/{prompt_hash}.json`：
json
{
"prompt_hash": "sha256:def456...",
"model": "qwen25-7b",
"temperature": 0,
"response": "...",
"created_at": "2026-01-15T10:00:00+08:00"
}
纯文本
- 仅缓存 `temperature=0` 的确定性输出
- 模型更新后自动失效

## 八、备份与恢复

### 8.1 写前备份（决策 6）

**流程**：写文件前，将原文件复制到 `backups/{批次时间戳}/`（结构见 `21-更新与回滚.md` §3）。
写操作触发
│
▼
检查目标文件是否存在
│
├─ 存在 → 复制到 backups/（异步，不阻塞写）
│
└─ 不存在 → 跳过备份
│
▼
执行写操作
纯文本
### 8.2 备份目录结构

统一使用 `21-更新与回滚.md` §3.2 的批次结构（按时间戳分目录 + 路径编码文件名 + `latest` 软链），此处不再重复定义。

### 8.3 备份清理

- 按 `21-更新与回滚.md` §3.3 保留策略：默认保留 30 天、总大小 1GB、单批次 100 文件（可配置 `backup_retention_days` / `max_total_size_mb`）
- 超期/超限自动清理（启动时检查）
- 用户可手动清理：`设置 → 备份管理 → 删除`

### 8.4 恢复

- 前端提供恢复界面：选择备份文件 → 预览 diff → 确认恢复
- 恢复操作本身也触发写前备份

## 九、日志存储

### 9.1 日志配置（tracing crate）
rust
// 伪代码：日志初始化
tracing_subscriber::fmt()
.with_file(true)
.with_line_number(true)
.with_thread_ids(true)
.with_max_level(Level::INFO)
.with_writer(make_writer::File::new("logs/app.log"))
.init();
纯文本
### 9.2 日志轮转

- 单个日志文件最大 10MB
- 超过后轮转：`app.log.1`, `app.log.2`, ...（最多保留 5 个）
- 审计日志 `audit.log` 同样按 10MB × 5 轮转，总上限 500MB（见 `22-安全模型.md` §7.1 / 决策 24）

### 9.3 审计日志格式

`logs/audit.log`（每行一个 JSON 对象）：
json
{"timestamp":"2026-01-15T10:00:00+08:00","event":"permission_check","level":"L2","tool":"write_file","path":"src/main.rs","result":"allowed","user_confirmed":true}
{"timestamp":"2026-01-15T10:01:00+08:00","event":"tool_call","tool":"git_commit","args":{"message":"refactor: main.rs"},"result":"success"}
纯文本
## 十、数据迁移与版本

### 10.1 Schema 版本

每个数据文件包含 `schema_version` 字段，用于迁移检测。

### 10.2 迁移流程

见 `19-数据迁移.md`，核心步骤：
1. 启动时检测数据目录 schema 版本
2. 对比当前代码期望版本
3. 执行迁移脚本（如有差异）
4. 迁移前自动备份

## 十一、安全约束

| 约束 | 说明 |
|------|------|
| 路径遍历防护 | 所有文件路径解析后必须在 `AI_ASSISTANT_DATA` 内 |
| 符号链接限制 | 备份模块解析真实路径，拒绝跨目录符号链接 |
| 权限检查 | 子 Agent 不可直接读写 `memory/shared/` |
| 加密存储 | 阶段 4+ 敏感记忆和 secrets.json 加密 |
| 审计日志 | 所有写操作记录审计日志 |
