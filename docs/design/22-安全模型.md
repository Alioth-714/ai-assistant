# 22 - 安全模型

> 状态：已定稿 | 最后更新：2026-01-15 | 关联：03-权限模型.md、04-数据边界.md、05-失败处理.md、21-更新与回滚.md

## 一、概述

安全模型定义 ai-assistant 系统在**数据保护、访问控制、威胁防御和审计**四个维度的安全边界与机制。系统定位为纯本地运行的个人 AI 助手，安全模型以此为前提设计：**数据不出本机、最小权限、默认拒绝、纵深防御。**

**核心目标**：
- 保护用户数据（代码、记忆、知识库）不被未授权访问或泄露
- 防止外部内容（网页、文档）对系统造成注入攻击或越权操作
- 确保多 Agent 协作时各组件互不越权
- 提供完整的安全审计能力

## 三、身份与信任

### 3.1 用户身份

- 系统为单用户本地应用，**不实现多用户认证**
- 用户身份等同于操作系统当前登录用户
- 敏感操作（L2/L3）通过弹窗确认，确认动作本身即身份核验
- 未来可选：添加应用级密码/生物识别解锁（阶段 4+）

### 3.2 进程间信任

| 进程 | 信任级别 | 通信方式 | 安全措施 |
|------|---------|---------|---------|
| 主协调者 ↔ 子 Agent | 高（同进程/本地 IPC） | stdio / 本地 socket | 进程隔离，消息签名 |
| 主协调者 ↔ Ollama | 中（本地 HTTP） | HTTP localhost | 仅监听 127.0.0.1，不暴露到网络 |
| 前端 ↔ 后端 | 高（Tauri IPC） | Tauri 命令 | 白名单命令，参数验证 |
| 工具层 ↔ 外部 | 低 | 网络/系统调用 | 权限网关拦截 |

### 3.3 模型来源验证

- Ollama 拉取的模型通过 checksum 验证
- 禁止加载来源不明的模型文件（非 ollama.com 官方仓库）
- 模型更新时校验签名（若 Ollama 支持）

## 四、访问控制

### 4.1 权限分级（详见 `03-权限模型.md`）

| 级别 | 说明 | 确认要求 |
|------|------|---------|
| L0 | 只读·安全 | 无需确认 |
| L1 | 只读·外部 | 无需确认（受网络策略约束） |
| L2 | 写操作·本地 | 必须确认 |
| L3 | 危险操作 | 必须确认 + 二次警告 |

### 4.2 角色约束

- 每个角色 YAML 声明 `max_permission`，子 Agent 派发受此上限约束
- 角色间数据隔离：记忆/知识按角色分层，子 Agent 不可跨角色访问

### 4.3 工具绑定

- 工具集按 Agent 类型固定绑定（决策 7）
- 子 Agent 只能调用绑定列表内的工具，不可动态加载新工具
- 工具调用统一经权限网关检查

### 4.4 网络策略（决策 17）

| 域名类型 | 处理方式 |
|---------|---------|
| `docs.*`、`wiki.*`、`github.com` | 默认允许（可配置开关） |
| 其他域名 | 首次访问询问用户 |
| 用户选择"始终允许" | 加入会话白名单 |
| 用户选择"拒绝" | 记录拒绝列表 |

详细见 `03-权限模型.md` §4.1。

## 五、威胁防御

### 5.1 Prompt 注入防护

**威胁**：外部内容（网页抓取、文档）可能包含恶意指令，试图覆盖系统 prompt、泄露上下文或诱导危险操作。

**防护措施**（决策 28）：

| 措施 | 说明 |
|------|------|
| 数据标记 | 外部内容注入时添加 `[EXTERNAL: {url}]` 前缀 |
| 指令过滤 | 检测 `system:`、`ignore previous`、`do anything` 等关键词，命中则警告并截断 |
| 上下文隔离 | 外部内容只作为"数据"注入，不作为"指令"；子 Agent 上下文与主协调者分离 |
| 输出审查 | 子 Agent 返回结果含疑似指令模式时，主协调者审查后再展示 |
| 权限限制 | 外部内容触发的操作仍受权限网关约束 |

### 5.2 输入验证

- 所有用户输入和工具参数经过类型检查和范围验证
- 文件路径参数：解析为绝对路径，检查是否在允许目录内（防路径遍历）
- URL 参数：校验协议（仅允许 http/https），检查域名策略
- JSON 解析：严格模式，拒绝重复字段和超长输入

### 5.3 输出过滤

- 子 Agent 输出中的文件路径、代码片段经过审查，防止路径泄露
- 敏感信息（API Key、密码）检测：正则匹配常见模式，命中则脱敏

### 5.4 沙箱（未来规划）

- 阶段 4+ 考虑对子 Agent 执行环境进行沙箱隔离（如 Windows Job Objects）
- 限制子 Agent 可访问的文件系统和网络资源

## 六、数据安全

### 6.1 存储加密

| 数据类型 | 当前（阶段 0-2） | 阶段 4+（决策 28） |
|---------|----------------|-------------------|
| 配置文件 | 明文 JSON | 可选加密（AES-GCM） |
| 知识库 | 明文 JSON | 明文（非敏感） |
| 记忆 | 明文 JSON | 敏感记忆加密（AES-GCM，密钥由用户口令派生） |
| 工作区 | 明文 JSON | 明文（临时） |
| 备份 | 明文 | 可选加密 |
| 日志 | 明文 | 敏感字段脱敏 |

### 6.2 密钥管理

- 阶段 0-2 以本地为主：未配置云端 Key 时恒为纯本地，无云端密钥需求（本地不足的难点转「能力不足」提示，见 `roadmap/18-本地云端边界方案.md`）
- 阶段 0-2 起若按 `roadmap/18` 启用云端兜底（OpenAI 兼容平台名+Key，见 `ops/12-模型部署.md` §云端兜底）时：
  - Key 存储在 `config/secrets.json`，文件权限限制为当前用户只读
  - 内存中解密使用，不写入日志
  - 支持用户通过 UI 管理
  - 三条约束：① 开了才用 ② 发前脱敏 ③ 传图先问（决策 18）

### 6.3 数据出境控制（详见 `04-数据边界.md`）

- 数据默认不出本机
- 云端只接脱敏描述（不含代码/路径/记忆）
- 外部内容抓取需用户确认（陌生域名）
- 审计日志记录所有网络访问

### 6.4 数据销毁

- 工作区任务结束立即销毁
- 孤儿工作区 24h 清理
- 备份按保留策略自动删除
- 日志轮转，超上限删除最旧
- 用户可手动触发"彻底清理"（清空缓存/日志/备份）

## 七、审计与监控

### 7.1 审计日志

所有安全相关事件记录到 `AI_ASSISTANT_DATA/logs/audit.log`：

| 事件类型 | 记录内容 |
|---------|---------|
| 权限拒绝 | 时间戳、工具、级别、原因 |
| 用户确认 | 时间戳、工具、用户选择 |
| 网络访问 | 时间戳、URL、域名、用户选择 |
| 写前备份 | 时间戳、目标文件、备份路径 |
| 文件锁冲突 | 时间戳、文件、请求者、持有者 |
| 注入检测 | 时间戳、来源、匹配模式、动作 |
| 回滚操作 | 时间戳、类型、涉及文件、结果 |

日志轮转：单文件 10MB，保留 5 个，总上限 500MB。

### 7.2 异常检测

- 连续多次权限拒绝 → 可能配置错误或恶意请求
- 短时间内大量网络请求 → 可能爬虫或注入尝试
- 异常文件访问模式 → 可能路径遍历攻击
- 检测到后记录警告日志，可配置触发用户通知

### 7.3 审计报表

用户可请求生成安全审计报表：
- 时间范围内的所有安全事件
- 权限使用统计
- 网络访问域名分布
- 回滚/备份操作汇总

## 八、安全开发生命周期

### 8.1 依赖管理

- 定期更新 Rust 依赖（`cargo audit`）
- 锁定关键依赖版本（Cargo.lock）
- 禁止使用已知漏洞的 crate

### 8.2 错误处理

- 库代码使用 `thiserror`（决策 25）
- 顶层使用 `anyhow`
- 错误信息不暴露内部路径或敏感数据
- 用户可见错误为友好提示，详细错误记录日志

### 8.3 安全测试

- 阶段 3+ 引入安全测试：注入攻击模拟、权限绕过测试
- 定期代码审查（人工 + 工具）

## 九、与外部系统的安全交互

### 9.1 Git 集成（决策 23）

- 使用 Git 命令行调用（非 libgit2），避免库漏洞
- Agent 可执行 `git status`、`git diff`、`git log`、`git commit`
- 禁止 Agent 执行 `git push`（需用户手动）
- 敏感仓库配置（如 credentials）不暴露给 Agent

### 9.2 浏览器/外部链接

- 链接抓取缓存独立目录 `cache/external/`
- 抓取内容标记为外部数据，不执行
- 多模态图片询问用户"传云端分析还是跳过？"（决策 18）

### 9.3 Ollama 通信

- 仅通过 `http://127.0.0.1:11434` 通信
- 使用 `ollama-rs` crate（决策 22）
- 不传输敏感数据到 Ollama（Ollama 本地运行，但模型可能输出敏感内容 → 输出过滤）

## 十、安全配置清单

用户部署时应检查：

- [ ] `AI_ASSISTANT_DATA` 目录权限：仅当前用户可访问
- [ ] Ollama 仅监听 localhost（默认）
- [ ] 防火墙未放行 11434 端口到外部
- [ ] `config/app.json` 中 `network.allowed_domains` 配置合理
- [ ] 日志目录大小在限制内
- [ ] 备份目录定期清理
