# 20 - 运行环境适配

> 状态：已定稿 | 最后更新：2026-01-15 | 关联：02-架构设计.md、05-失败处理.md、03-权限模型.md、ops/14-开发环境.md

## 一、概述

ai-assistant 需适配多样化的本地运行环境。本文档定义系统启动时的环境检测、依赖校验、自适应配置和降级策略，确保在不同硬件和网络条件下均可正常运行。

**核心目标**：
- 启动时自动检测环境能力（GPU、内存、磁盘、Ollama 状态）
- 根据检测结果自适应调整运行参数（并发数、模型精度、缓存大小）
- 依赖缺失或版本不匹配时给出明确指引
- 支持离线模式（纯本地推理，无外网）

## 二、系统要求

### 2.1 最低要求

| OS | Windows 10 1903+ / Linux kernel 5.4+ / macOS 12+ | Windows 为首要支持平台（用户环境） |

| 组件 | 规格 |
|------|------|

| 内存 | 16GB DDR4（金百达 8G×2） |
| GPU | NVIDIA RTX 2070 8GB GDDR6 |
| 存储 | 建议 NVMe SSD（数据目录所在盘） |

### 2.3 磁盘空间规划

| 目录 | 预估大小 | 增长策略 |
|------|---------|---------|
| `config/` | < 1MB | 固定 |
| `knowledge/` | 10-500MB | 用户控制 |
| `memory/` | 1-50MB | 自动积累，可清理 |
| `workspace/` | 临时，< 100MB/任务 | 任务结束销毁 |
| `backups/` | 按保留策略，默认 < 1GB | 30 天自动清理 |
| `cache/` | < 2GB | 可手动清理 |
| `logs/` | < 500MB（轮转上限） | 超上限自动删除最旧 |
| **总计** | **< 20GB** | 硬性上限（决策补充） |

## 三、核心依赖

### 3.1 Ollama（本地推理引擎）

| 项目 | 说明 |
|------|------|
| 版本要求 | Ollama 0.3.0+ |
| 通信方式 | `ollama-rs` crate（决策 22） |
| 默认地址 | `http://127.0.0.1:11434` |

| 可选模型 | 其他量化版本（根据用户硬件选择） |

**启动检测流程**：
程序启动
│
▼
尝试连接 Ollama（http://127.0.0.1:11434/api/tags）
│
├─ 连接失败 → 提示用户："Ollama 未运行，请启动后重试"
│ 提供启动命令：ollama serve
│ 重试 3 次，间隔 2 秒（网络型失败，见 05 §6.1）
│
└─ 连接成功 → 获取已安装模型列表
│
├─ 缺少必需模型 → 提示用户安装
│ 显示命令：ollama pull qwen25-3b / qwen25-7b（light/heavy）
│ 可自动执行（用户确认后）
│
└─ 模型就绪 → 继续启动
纯文本

## 四、环境检测与自适应

### 4.1 GPU 检测

启动时通过 `nvidia-smi`（Windows）或 `nvml` 检测 GPU 信息：
rust
// 伪代码
fn detect_gpu() -> GpuInfo {
let output = Command::new("nvidia-smi")
.args(["--query-gpu=name,memory.total,memory.free", "--format=csv,noheader,nounits"])
.output();
// 解析输出
}
纯文本
**自适应策略**：

| 检测结果 | 调整行为 |
|---------|---------|
| RTX 2070 / 8GB | 路由 3B 常驻 GPU，主协调者 8B 优先 GPU（offload），子 Agent 按需加载 |
| 无 GPU / 显存 < 4GB | 全部 CPU 推理，并发上限降为 1 |
| 显存 4-6GB | 3B 常驻 GPU，8B 走 CPU |
| 显存 > 12GB | 3B + 8B 均可常驻 GPU，子 Agent 可并行 |

### 4.2 内存检测

| 可用内存 | 行为调整 |
|---------|---------|
| > 12GB | 正常模式，工作区缓存上限 500MB |
| 8-12GB | 保守模式，工作区缓存上限 200MB，减少并发 |
| < 8GB | 最小模式，禁用工作区缓存，串行执行 |

### 4.3 Ollama 模型可用性

启动时检查模型是否可用，并获取模型信息：
json
{
"models": {
"qwen25-3b": {
"available": true,
"quantization": "Q4_K_M",
"context_length": 32768
},
"qwen25-7b": {
"available": true,
"quantization": "Q4_K_M",
"context_length": 32768
}
}
}
纯文本
若模型不存在，提示用户拉取，或提供自动拉取选项。

### 4.4 磁盘空间检测

启动时检查 `AI_ASSISTANT_DATA` 所在磁盘的可用空间：

| 可用空间 | 行为 |
|---------|------|
| > 5GB | 正常 |
| 1-5GB | 警告，建议清理缓存 |
| < 1GB | 阻止启动，要求释放空间 |

## 五、配置管理

### 5.1 配置文件格式（决策 21）

- 格式：JSON
- 缩进：2 空格
- 字段排序：按字母序
- 注释：使用 `_comment` 字段
json
{
"_comment": "ai-assistant 主配置文件",
"data_root": "E:/ai-assistant/data",
"log_level": "info",
"max_concurrent_agents": 2,
"models": {
"coordinator": "qwen25-7b",
"router": "qwen25-3b",
"sub_agent_light": "qwen25-3b",
"sub_agent_heavy": "qwen25-7b"
},
"network": {
"allowed_domains": ["docs.", "wiki.", "github.com"],
"ask_on_first_access": true
},
"ollama": {
"host": "http://127.0.0.1:11434",
"keep_alive": 300
}
}
纯文本
### 5.2 配置加载优先级

1. 命令行参数（最高）
2. 环境变量（`AI_ASSISTANT_*`）
3. 配置文件（`AI_ASSISTANT_DATA/config/app.json`）
4. 内置默认值（最低）

### 5.3 首次启动

首次启动时无配置文件，执行初始化向导：
1. 选择数据目录（默认：`{程序目录}/data/` 或用户指定）
2. 检测 Ollama 并选择模型
3. 生成默认 `app.json`
4. 创建目录结构

## 六、开发环境 vs 生产环境

| 维度 | 开发环境 | 生产环境 |
|------|---------|---------|
| 日志级别 | `debug` | `info` |
| 日志输出 | 终端 + 文件 | 仅文件（可配置） |
| 热重载 | 支持（前端） | 不支持 |
| 断言 | 启用 | 禁用（替换为日志） |
| 错误展示 | 详细堆栈 | 用户友好提示 + 错误 ID |
| 性能监控 | 启用（耗时统计） | 可选 |

通过 `app.json` 中 `"env": "development" | "production"` 切换。

## 七、网络环境适配

### 7.1 代理支持

- 读取系统代理设置（Windows: `Internet Options`）
- 支持 `HTTP_PROXY` / `HTTPS_PROXY` 环境变量
- 配置项可覆盖：`app.json` → `network.proxy`

### 7.2 离线模式

当检测到无网络连接时：
- 自动切换到离线模式
- 禁用所有外网功能（链接抓取、云端模型）
- 知识库只能使用本地已有内容
- 提示用户："当前处于离线模式，部分功能不可用"

### 7.3 网络策略适配

- 企业网络可能屏蔽 Ollama 默认端口 → 支持配置自定义端口
- 防火墙拦截 → 提示用户放行 11434 端口

## 八、降级策略

当环境不满足推荐配置时，系统自动降级以保证基本功能可用：

| 降级场景 | 降级行为 |
|---------|---------|
| GPU 不可用 | 全部 CPU 推理，关闭子 Agent 并发 |
| 内存不足 | 减少工作区缓存，串行化任务 |
| Ollama 连接失败 | 提示用户检查，支持重试；不可用时拒绝启动 |
| 模型缺失 | 提示用户拉取；若用户选择跳过，使用云端兜底（需配置） |
| 磁盘空间不足 | 清理缓存 → 清理旧日志 → 仍不足则阻止写操作 |

## 九、硬件升级建议（未来）

若长期运行，升级优先级（来自总纲）：

- **第一优先**：内存加到 32GB（16G×2 替换 8G×2）——模型常驻 + IDE + Chrome + DB 不再冲突，收益最大
- **第二优先**：显卡换 12GB / 24GB——12GB 可跑 14B，24GB 可跑 32B Q4；RTX 2070 现阶段够 MVP
- CPU 暂不动：10400F 跑 agent 编排够用，换 CPU 需连主板一起换，不值
