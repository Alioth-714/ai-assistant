# 21 - 更新与回滚

> 状态：已定稿 | 最后更新：2026-01-15 | 关联：05-失败处理.md、19-数据迁移.md、03-权限模型.md、ops/14-开发环境.md

## 一、概述

系统运行过程中涉及多种"变更"操作：程序版本升级、模型切换、配置修改、知识库更新、文件写操作等。本文档定义这些变更的**安全更新流程**和**回滚机制**，确保任何变更都可逆。

**核心原则**（决策 6）：
- **写前备份**：任何写操作执行前，先备份目标文件到 `AI_ASSISTANT_DATA/backups/`
- **变更可回滚**：所有变更操作必须能提供回滚路径
- **原子性**：变更要么完全成功，要么完全回滚，不允许中间状态

## 二、更新类型

| 类型 | 触发者 | 风险级别 | 备份要求 |
|------|--------|---------|---------|
| 程序更新 | 用户/自动 | 高 | 备份可执行文件+配置 |
| 模型切换 | 用户/主协调者 | 中 | 备份模型配置 |
| 配置修改 | 用户/程序 | 低-中 | 备份被修改的配置文件 |
| 知识库更新 | Agent/用户 | 低 | 备份被修改的知识文件 |
| 记忆更新 | Agent/用户 | 低 | 备份被修改的记忆文件 |
| 文件写操作（L2） | 子Agent/主协调者 | 中-高 | 备份目标文件（写前备份） |
| Git 操作 | 用户/Agent | 中 | Git 自身提供回滚（commit/reset） |

## 三、写前备份机制

### 3.1 备份触发

所有 L2（写操作·本地）和 L3（危险操作）级别的工具调用，在执行写操作前，必须触发备份。
工具调用（L2/L3）
│
▼
权限网关检查（见 03-权限模型.md）
│
▼
┌─────────────────────────┐
│ 备份模块（backup.rs） │
│ · 计算目标文件绝对路径 │
│ · 检查文件是否存在 │
│ · 生成备份路径 │
│ · 复制文件到备份目录 │
└─────────┬───────────────┘
▼
执行原写操作
│
├─ 成功 → 记录备份映射（用于后续回滚）
└─ 失败 → 无需回滚（文件未被修改）
纯文本
### 3.2 备份路径规则
AI_ASSISTANT_DATA/backups/
├── 2026-01-15T14:30:00+08:00/ # 按时间戳分目录（一次变更批次）
│ ├── config_app.json.bak # 原路径编码到文件名
│ ├── knowledge_dev_rust-traits.json.bak
│ └── src_main.rs.bak
├── 2026-01-15T15:00:00+08:00/
│ └── ...
└── latest -> 2026-01-15T15:00:00+08:00/ # 软链接指向最新备份（Windows 为 junction）
纯文本
**文件名编码规则**：
- 将绝对路径中的 `/` 和 `\` 替换为 `_`
- 去除盘符冒号（Windows）
- 添加 `.bak` 后缀

示例：`C:\MyProject\src\main.rs` → `C_MyProject_src_main_rs.bak`

### 3.3 备份保留策略

| 策略项 | 默认值 | 可配置 |
|--------|--------|--------|
| 单批次备份上限 | 100 个文件 | 是（`max_files_per_batch`） |
| 备份目录总大小上限 | 1GB | 是（`max_total_size_mb`） |
| 备份保留时间 | 30 天 | 是（`retention_days`） |
| 自动清理 | 启用 | 是 |

清理逻辑：启动时检查 → 删除超过保留时间的备份批次 → 若总大小仍超限，按时间从旧到新删除直到满足上限。

### 3.4 备份与锁的关系

- 备份操作本身**不需要文件锁**（只读复制）
- 备份完成后，写操作才获取文件锁（见 `05-失败处理.md` §2）
- 顺序：备份 → 获取锁 → 写入 → 释放锁

## 四、程序更新流程

### 4.1 更新检测

- 启动时检查远程版本（可选，受网络策略约束）
- 用户手动触发检查
- 发现新版本 → 显示更新日志 → 用户确认

### 4.2 更新执行
用户确认更新
│
▼
1.
备份当前程序目录（可执行文件 + 依赖库）
→ AI_ASSISTANT_DATA/backups/update{version}{timestamp}/
│
▼
2.
下载新版本（到临时目录）
│
▼
3.
验证签名/校验和
│
├─ 验证失败 → 删除临时文件 → 报告用户
│
└─ 验证成功 → 停止当前服务（Ollama 连接等）
│
▼
4.
替换程序文件
│
▼
5.
启动新版本
│
▼
6.
运行迁移检查（见 19-数据迁移.md）
│
▼
7.
更新完成 / 失败回滚
纯文本
### 4.3 回滚

若更新后程序无法启动：
1. 用户手动执行回滚命令：`ai-assistant rollback`
2. 从 `backups/update_*/` 恢复程序文件
3. 若数据格式已迁移，同时回滚数据（见 19-数据迁移.md）

## 五、模型切换

### 5.1 切换流程
用户/Agent 请求切换模型
│
▼
检查目标模型是否已下载
│
├─ 未下载 → 提示用户拉取（ollama pull）
│
└─ 已下载 → 检查显存是否足够
│
├─ 不足 → 提示用户（关闭其他模型/使用云端）
│
└─ 足够 → 备份当前模型配置
→ 修改 app.json 中 models.* 字段
→ 热切换（若支持）或提示重启
纯文本
### 5.2 回滚

- 模型切换只修改配置，不涉及数据变更
- 回滚：恢复 `app.json` 中 `models` 字段到之前的值

## 六、配置修改

### 6.1 修改前备份

任何对 `config/app.json` 的修改（用户手动或程序自动）前：
1. 复制当前 `app.json` → `backups/config/app_{timestamp}.json`
2. 执行修改
3. 验证 JSON 格式正确

### 6.2 格式错误恢复

若修改后的 `app.json` 解析失败：
1. 自动从最近备份恢复
2. 记录错误日志
3. 提示用户手动修复

## 七、知识库与记忆更新

### 7.1 单文件更新

Agent 或用户修改知识/记忆文件时：
1. 备份原文件到 `backups/knowledge/` 或 `backups/memory/`
2. 执行修改（写入新内容）
3. 验证 JSON 格式

### 7.2 批量更新（如导入）

1. 创建批次备份目录
2. 逐文件备份 → 修改
3. 任一失败 → 回滚该批次所有修改

### 7.3 版本字段

知识/记忆 JSON 中包含 `schema_version`，更新时若格式变化，触发迁移（见 19-数据迁移.md）。

## 八、Git 操作回滚

Agent 执行的 Git 操作（如 `git commit`、`git checkout`）的回滚：

| 操作 | 回滚命令 |
|------|---------|
| `git commit` | `git reset --soft HEAD~1` |
| `git checkout` | `git checkout -` |
| `git merge` | `git merge --abort` |
| `git rebase` | `git rebase --abort` |
| `git push`（已推送） | 需用户确认，不自动回滚 |

**规则**：Agent 创建的 commit 可由 Agent 回滚（L2 需确认）；已 push 到远程的变更不自动回滚。

## 九、回滚操作汇总

### 9.1 用户触发回滚

用户可通过以下方式触发回滚：
- UI 操作："回滚到上次修改"
- 命令行：`ai-assistant rollback [--task-id <id>] [--file <path>]`
- 对话指令："撤销刚才的操作"

### 9.2 自动回滚（失败处理）

当操作失败且检测到已产生副作用时（见 `05-失败处理.md` §6）：
1. 查找当前批次备份
2. 按修改逆序恢复文件
3. 验证恢复结果
4. 报告用户

### 9.3 回滚范围矩阵

| 变更类型 | 回滚粒度 | 自动回滚 | 手动回滚 |
|---------|---------|---------|---------|
| 单文件写 | 单文件 | 是 | 是 |
| 多文件写 | 批次 | 是 | 是 |
| 配置修改 | 单配置 | 是 | 是 |
| 知识库更新 | 单文件/批次 | 是 | 是 |
| 记忆更新 | 单文件 | 是 | 是 |
| 程序更新 | 全量 | 否（需用户触发） | 是 |
| 模型切换 | 配置 | 否 | 是 |
| Git 操作 | 单操作 | 部分（见 §8） | 是 |

## 十、与失败处理的关系

- **失败处理**（`05-失败处理.md`）：关注运行时错误恢复，强调"重试→回滚→报告"
- **更新与回滚**（本文档）：关注变更操作的安全保障，强调"写前备份→可回滚"
- 两者交集：当失败处理决定回滚时，调用本文档定义的回滚机制

## 十一、审计日志

所有备份和回滚操作记录到 `AI_ASSISTANT_DATA/logs/backup.log`：

| 事件 | 记录内容 |
|------|---------|
| 备份创建 | 时间戳、源文件、备份路径、批次 ID |
| 备份清理 | 时间戳、删除的批次/文件、释放空间 |
| 回滚执行 | 时间戳、回滚类型、涉及文件、结果 |
| 回滚失败 | 时间戳、失败原因、建议操作 |
