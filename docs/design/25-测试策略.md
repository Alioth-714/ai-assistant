# 25 - 测试策略

> 状态：已定稿 | 最后更新：2026-01-15 | 关联：02-架构设计.md、03-权限模型.md、05-失败处理.md、22-安全模型.md、24-前端交互设计.md

## 一、概述

ai-assistant 作为本地多 Agent 协作系统，涉及模型推理、工具调用、权限控制、数据持久化等多个复杂环节。测试策略确保各层组件正确协作，并在变更后维持系统稳定性。

**测试目标**：
- 验证四层架构（路由→角色→主协调者→子Agent）的协作正确性
- 确保权限网关、数据边界、失败处理等安全机制不被绕过
- 验证在目标硬件（i5-10400F + RTX 2070 + 16GB）上的性能表现
- 保障写前备份、回滚等关键数据操作的可靠性

**测试原则**：
- 单元测试覆盖核心逻辑（Rust 库代码）
- 集成测试覆盖多组件交互（Agent 协作、工具调用）
- 端到端测试覆盖用户可见流程（对话→任务执行→结果展示）
- 所有测试可离线运行（不依赖外部网络，除非显式测试网络功能）

## 二、测试分层

| 层级 | 范围 | 工具 | 执行频率 |
|------|------|------|---------|
| 单元测试 | 单个函数/模块（工具实现、权限检查、JSON 解析） | `cargo test` | 每次构建 |
| 集成测试 | 多模块协作（主协调者派发任务、权限网关拦截、工作区读写） | `cargo test --test` | 每次 PR/提交 |
| 端到端测试 | 完整用户流程（前端输入→后端处理→前端展示） | Tauri test harness + 手动 | 发布前 |
| 性能测试 | 显存占用、token 处理速度、并发上限 | 自定义 benchmark | 版本迭代 |
| 安全测试 | 注入防护、权限绕过、数据泄露 | 专项测试脚本 | 版本迭代 |

## 三、单元测试

### 3.1 范围

| 模块 | 测试重点 |
|------|---------|
| `src/gateway/permission.rs` | 权限级别判定、角色上限检查、L1 与网络策略正交逻辑 |
| `src/tools/` | 各工具参数验证、路径遍历防护、返回值格式 |
| `src/workspace/` | 工作区创建/销毁、文件锁 JSON 读写、孤儿清理 |
| `src/memory/` | 记忆分层读取、写入隔离、JSON schema 验证 |
| `src/knowledge/` | 知识检索（关键词→向量）、注入过滤、链接抓取缓存 |
| `src/coordinator/` | 上下文摘要压缩、任务拆解逻辑、子 Agent 结果汇总 |
| `src/error.rs` | 错误类型定义（thiserror）、顶层 anyhow 转换 |

### 3.2 约定

- 使用 `#[cfg(test)] mod tests` 内联测试或 `tests/` 目录
- Mock 外部依赖（Ollama 推理返回固定响应、文件系统使用临时目录）
- 错误处理测试：验证 `thiserror` 定义的错误能被正确捕获和转换

## 四、集成测试

### 4.1 多 Agent 协作流程

**测试场景**：

| 场景 | 验证点 |
|------|--------|
| 主协调者派发任务→子 Agent 认领→完成 | 广播/认领机制、工作区数据传递 |
| 子 Agent 写文件冲突 | 文件锁生效、等待/重试逻辑 |
| 子 Agent 失败→重试→回滚 | 失败处理流程（决策 3）、备份恢复 |
| 上下文超 70% → 外移数据 | 指针替换、摘要压缩 |
| 角色切换 | 上下文存缓存池、新角色加载正确工具集 |

**测试方法**：
- 使用测试专用的 `AI_ASSISTANT_DATA` 临时目录
- Mock Ollama 返回预设的路由结果和子 Agent 响应
- 验证工作区 JSON、备份文件、锁文件的最终状态

### 4.2 权限网关集成

| 场景 | 验证点 |
|------|--------|
| L2 操作弹出确认 | 网关返回 `PendingConfirmation`，等待用户响应 |
| 角色权限上限拦截 | 角色 max_permission=L2 时，L3 操作被拒绝 |
| 文件写保护 | 敏感路径（memory/）被子 Agent 访问时拒绝 |
| 网络域名首次询问 | 陌生域名触发询问，用户选择后加入白名单 |

### 4.3 工具层集成

| 场景 | 验证点 |
|------|--------|
| Git 命令行调用（决策 23） | `git commit` 成功、`git push` 被禁止 |
| 文件读写+备份 | 写前备份生成、原文件正确修改 |
| 外部链接抓取 | 缓存写入 `cache/external/`、内容标记外部来源 |

## 五、端到端测试

### 5.1 测试环境

- 硬件：用户环境（i5-10400F + RTX 2070 8GB + 16GB RAM）
- OS：Windows 10/11（PowerShell）
- 依赖：Ollama 0.3.0+（含 qwen25-3b / qwen25-7b）

### 5.2 关键用户流程

| 流程 | 步骤 | 验证点 |
|------|------|--------|
| 首次启动 | 启动→初始化向导→配置→就绪 | 目录结构创建、默认配置生成 |
| 对话+任务执行 | 用户输入→路由→角色→主协调者→子Agent→结果 | 流式输出、任务进度、最终 diff |
| 权限确认 | 触发 L2 操作→弹窗→用户允许→执行 | 弹窗内容正确、审计日志记录 |
| 失败+回滚 | 诱导写失败→系统重试→回滚→报告 | 备份存在、文件恢复原状 |
| 知识库添加 | 用户提供链接→抓取→总结→保存 | 知识 JSON 正确、检索可用 |

### 5.3 前端测试

- Tauri 命令调用：验证 `invoke` 参数和返回值
- 事件监听：模拟后端推送 `stream_chunk`、`permission_request`
- UI 交互：手动测试为主（纯 HTML/CSS/JS，无框架测试工具链）

## 六、性能测试

### 6.1 显存与并发

| 测试项 | 方法 | 预期 |
|--------|------|------|
| 3B 路由常驻 + 8B 主协调者常驻 | 启动后 `nvidia-smi` 查看 | 总显存 < 6.5GB |
| 子 Agent 并发上限 | 派发 3 个 3B 子 Agent | 第 3 个排队或降级 CPU |
| 长时间运行内存泄漏 | 连续 50 轮对话 | 内存增长 < 100MB |

### 6.2 Token 处理

| 测试项 | 方法 | 预期 |
|--------|------|------|
| 3B 4K 上限 | 注入超长上下文 | 触发截断/外移，不崩溃 |
| 8B 8K 上限 | 跨文件重构任务 | 分段处理，增量 diff 正确 |
| 摘要压缩 | 上下文达 90% | 压缩后保留关键决策，token 数下降 >30% |

### 6.3 工具调用延迟

| 工具 | 预期延迟（本地） |
|------|----------------|
| read_file | < 50ms |
| write_file（含备份） | < 200ms |
| grep | < 100ms |
| git_status | < 500ms |
| web_fetch（本地缓存命中） | < 100ms |

## 七、安全测试

### 7.1 Prompt 注入

| 测试用例 | 预期结果 |
|---------|---------|
| 外部网页含 `ignore previous instructions` | 被过滤/截断，不作为指令执行 |
| 知识库 JSON 中嵌入系统指令 | 注入时标记外部来源，主协调者过滤 |
| 用户输入尝试提权命令 | 权限网关拦截，L3 需二次确认 |

### 7.2 权限绕过

| 测试用例 | 预期结果 |
|---------|---------|
| 子 Agent 尝试直接读 `memory/shared/` | 拒绝，子 Agent 不可见记忆 |
| 子 Agent 尝试写 `config/app.json` | 权限网关拒绝（超出角色 max_permission） |
| 工具调用伪造 L0 级别 | 网关从工具表查真实级别，不被欺骗 |

### 7.3 数据边界

| 测试用例 | 预期结果 |
|---------|---------|
| 工作区文件尝试写入 `../config/app.json` | 路径解析拦截（路径遍历防护） |
| 网络请求携带代码内容 | 数据边界检查拒绝（高敏感数据不出境） |
| 备份目录被符号链接指向系统文件 | 备份模块解析真实路径，拒绝跨目录 |

## 八、测试数据管理

- 测试使用独立数据目录：`tests/fixtures/data/`
- 测试前自动清理、初始化
- 敏感测试（如加密）使用临时密钥，不硬编码
- 网络测试使用 mock server 或本地文件，避免依赖外部服务
