## 决策 1：混合模型 + 渐进升级

**结论**：轻活（单文件/只读/简单提取）→ 3B 子 Agent；重活（多文件/写操作/复杂推理）→ 7B 子 Agent；外部信息 → 云端 API（脱敏后）。3B 搞不定自动升级 7B，7B 搞不定走云端。
**判断者**：主协调者（7B），先探查（list_dir / grep）拿到文件数、操作类型后再决策，不凭空判断。
**理由**：8GB 显存装不下多个 7B 并行，按任务轻重分流才能保住体验与成本。
**落地**：`src/brain/orchestrator.rs`。

---

## 决策 2：子 Agent 共享数据（结构化 JSON 工作区）

**结论**：子 Agent 之间不直接传大段文本，写入 `AI_ASSISTANT_DATA/workspace/{task_id}/` 的结构化 JSON；后续 Agent 按需读取字段。
**生命周期**：任务创建时建、完成/取消时销毁；孤儿目录启动时扫描、超 24h 清理。task_id = 时间戳 + 短随机串（如 `20260115_a3f7`）。
**协作机制**：主协调者广播任务 → 子 Agent 按 capabilities 认领 → 主协调者确认派发 → 未认领部分直接指派（原「决策 6+10/11 广播→认领」并入本条）。
**理由**：多 Agent 不共享内存、不直接通信，工作区是唯一交换通道，可审计、可回滚、可断点续。
**落地**：`src/brain/task.rs` Workspace 结构（含原「工作区生命周期」）。

---

## 决策 3：失败处理流程

**结论**：失败 → 重试（按类型，见 `design/05-失败处理.md` §6.1）→ 检查原因 → 回滚已改文件 → 报告用户原因 + 修复方案 → 用户决定下一步。
**禁止**：自行降级到危险操作、静默吞错、无限重试。
**理由**：个人工具可靠性优先，宁可多问一次也不静默改数据。
**落地**：`src/brain/sub_agent.rs`、`src/error.rs`。

---

## 决策 4：禁止嵌套

**结论**：子 Agent 只能调工具，不能派子 Agent。需要额外信息 → 返回主协调者 → 由主协调者再派。
**理由**：防止循环调用、深度爆炸、失控与 token 烧穿。
**落地**：`src/agents/traits.rs`。

---

## 决策 5：用户感知

**结论**：默认静默（只显示「正在分析项目结构…」），可展开查看细节（「📊 代码分析Agent 正在读取文件… → 完成」）。关键事件（L2/L3 确认、失败、回滚）必须弹窗阻塞。
**理由**：多 Agent 后台事件多，全弹窗会把人烦走；确认与错误不能静默。
**落地**：Tauri 前端 + `src/brain/context.rs` 事件。

---

## 决策 6：回滚（文件级写前备份）

**结论**：任何 L2/L3 写操作执行前，先把目标文件备份到 `AI_ASSISTANT_DATA/backups/`，回滚 = 复制回来。备份结构（批次目录）、保留策略见 `design/21-更新与回滚.md`。
**顺序**：备份 → 获取文件锁 → 写入 → 释放锁。回滚不依赖 git。
**理由**：Agent 写文件是主要风险面，写前备份是「不丢数据」的底线。
**落地**：`src/gateway/backup.rs`。

---

## 决策 7：工具集固定绑定 Agent 类型

**结论**：每个子 Agent 创建时绑定工具集，运行时不可改。需要组合能力 = 选不同种类的 Agent。新增工具必须注册进权限网关并声明权限级别。
**理由**：缩小攻击面、防止 Agent 越权调工具。
**落地**：`src/agents/registry.rs`。

---

## 决策 8：Token 硬上限

**结论**：

| 角色 | 硬上限 |
|------|--------|
| 3B（路由 / 轻活子 Agent） | 4K |
| 7B（主协调者 / 重活子 Agent） | 8K |
| 云端 | 不限制（由 API 端决定） |

超限处理：外移指针 → 摘要压缩 → 硬截断 + 警告；跨文件重构按文件分段 + 增量 diff。
**理由**：本地小模型窗口有限，硬上限防止上下文膨胀烧穿显存与时间。
**落地**：`src/brain/sub_agent.rs`、`src/brain/context.rs`。

## 决策 9：主协调者上下文管理

**结论**：正常（外移）：子 Agent 详细结果存工作区，主协调者上下文只放指针 + 摘要，需要细节再读；兜底（压缩）：指针 + 摘要也堆满时摘要压缩（保留关键决策，外移历史）。预警线 70%、强制压缩线 90%。
**理由**：8K 窗口下要支撑长任务，只能靠外移 + 压缩两级兜底。
**落地**：`src/brain/context.rs`。

---

## 决策 10：角色切换常驻复用 + 缓存池

**结论**：主协调者实例（7B）保留，切换角色时上下文序列化存角色缓存池 `AI_ASSISTANT_DATA/cache/role_contexts/{role}.json`，切回来恢复继续工作。
**理由**：7B 加载慢，常驻复用是响应体验的关键。
**落地**：`src/brain/context.rs`、`src/roles/loader.rs`。

## 决策 11：记忆分层

**结论**：`memory/shared/`（公共，所有角色可读不可改）+ `memory/{role}/`（角色独立，不互相污染）。角色层不可改 shared，需更新由主协调者代理。
**理由**：角色隔离防污染，公共层承载用户画像与全局事实。
**落地**：`src/memory/`。

## 决策 12：知识库三层

**结论**：`knowledge/shared/`（所有角色可读不可改）+ `knowledge/general/`（通用）+ `knowledge/{custom_role}/`（角色专属）。
**理由**：知识共享与隔离并存，避免角色间污染。
**落地**：`src/knowledge/`。

## 决策 13：知识文件格式（结构化 JSON）

**结论**：每条知识独立 JSON，含 `schema_version / id / title / content / source / tags / created_at / updated_at / embedding`。
**理由**：人靠 AI 辅助编辑、可版本控制、可迁移（见 `19-数据迁移.md`）。
**落地**：`src/knowledge/store.rs`。

## 决策 14：检索策略（先关键词后向量）

**结论**：阶段 1-2 关键词匹配（keywords/title/content 计分排序，Top-K）；阶段 3+ 引入向量检索（embedding + 余弦，混合排序：向量 70% + 关键词 30%）。
**理由**：阶段早期关键词够用且零依赖，向量在知识量上来后再上。
**落地**：`src/memory/recall.rs` 预留接口。

## 决策 15：知识混合维护

**结论**：用户写骨架（`source: manual`）+ Agent 补充细节（`source: agent`），文件内标记来源；`hybrid` 为两者混合。
**理由**：知识可信度要可追溯，来源字段是审计基础。
**落地**：知识文件 `source` 字段。

## 决策 16：链接自主学习

**结论**：用户给链接 → 域名策略检查 → 抓取（存 `cache/external/`）→ 主协调者总结为知识条目 → 询问用户保存位置后写入知识库。频率限制：同域名 1 分钟 ≤ 5 次。
**理由**：外网内容进知识库必须人工兜底确认，防污染与注入。
**落地**：`src/tools/web_fetch.rs`、`src/knowledge/auto_learn.rs`。

## 决策 17：外网访问平衡策略

**结论**：常见文档站（`docs.*` / `wiki.*` / `github.com`）默认允许（可配置开关）；其他域名首次访问询问；会话内同域名只问一次；24 小时不重复询问；用户可「始终允许」进白名单或「拒绝」进拒绝列表。
**理由**：既保常用效率，又防隐私泄漏。
**落地**：`src/gateway/network.rs`。

## 决策 23：Git 集成 CLI 调用

**结论**：代码里调 `git diff / git log / git commit` 等命令行。Agent 可 commit（L2 需确认），**禁止 Agent 执行 `git push` / `git remote add`**（需用户手动）。回滚不依赖 git（决策 6 已定文件级备份）。

## 决策 25：错误处理混合

**结论**：库代码（core/models/brain 内部）用 `thiserror` 定义具名错误类型（调用方需区分重试/降级/上报）；顶层（main.rs）用 `anyhow` 快速失败，`?` 一路向上，最终统一转换用户友好消息。
**跨模块**：内部 thiserror，顶层转 anyhow。

## 决策 26：权限模型（L0-L3 分级 + 横切策略正交）

**结论**：L0 只读安全（免确认）、L1 只读外部（免确认，但受网络域名策略约束）、L2 写本地（弹窗确认）、L3 危险操作（确认 + 二次警告）。权限级别与网络访问/文件写保护等横切策略正交，按「先级别、后横切」顺序执行。详见 `design/03-权限模型.md`。
**理由**：单维分级不够，网络与文件保护是跨级别规则。
**落地**：`src/gateway/permission.rs`。

## 决策 27：数据边界

**结论**：数据默认不出本机；云端只接脱敏描述（去路径/密钥/内网地址/上下文无关片段）；外部内容只作数据不作指令；路径遍历防护（解析后必须落在允许基目录）。出境走审批流：高敏感强制拒绝 → 可脱敏则发脱敏版 → 域名策略放行/拒绝。详见 `design/04-数据边界.md`。
**理由**：本地优先 + 注入防护 + 防泄露三合一。
**落地**：`src/gateway/path.rs`、`src/gateway/network.rs`。

## 决策 28：安全模型

**结论**：Prompt 注入防护（外部内容标记 `[EXTERNAL:{url}]`、指令关键词过滤、子 Agent 上下文隔离、输出审查）；写操作互斥（文件锁，见 `05-失败处理.md` §2）；敏感记忆加密（阶段 4，AES-256-GCM，密钥由用户口令 **Argon2id** 派生）。详见 `design/22-安全模型.md`。
**理由**：本地助手直接操作文件/网络，注入与越权是主要威胁。
**落地**：`src/gateway/security.rs`、`src/crypto/`（阶段 4）。

## 决策 29：性能优化（显存调度等）

**结论**：RTX 2070 8GB 下统一资源调度：本地路由模型常驻 GPU（~2.5GB）；7B 主协调者常驻、GPU 分层按需 offload；子 Agent 3B 并发上限 2（第 1 个 GPU、第 2 个 CPU）、7B 子 Agent 走 CPU 或云端。写前备份异步化、上下文分段、工具结果缓存。详见 `design/27-性能优化.md`。
**理由**：8GB 装不下「轻量档（small）+多子 Agent」全常驻，必须定死一套不打架的调度模型。
**落地**：`src/models/scheduler.rs`。

## 决策 31：Planner 子层（2026-10-22 新增）

**结论**：主协调者的「任务拆解/派发」升级为 Planner 子层——**计划先行 + 单步决策**：先产出结构化 plan（步骤数组），模型每步只输出「下一步调哪个工具/参数」，工具结果由**代码显式拼接**注入下一步，绝不让模型跨步自持（阶段 2 实测多步链 100% 失败，见 `roadmap/18` §二）。
**范围**：第一版只做 **P1 模板状态机**（模板未命中 → 阶段 3 接云端拆 plan，A+C）。单步决策默认用大脑 `qwen25-7b`（唯一大脑，2026-10-22 移除 8b）。步数上限 + 调用去重硬卡循环。
**落地**：`src/planner/`（plan.rs / templates.rs / executor.rs）。详见 `modules/07-主协调者.md` §十。

## 决策 32：Tool Guard 子层（2026-10-22 新增）

**结论**：工具调用加确定性守卫（**纯代码、零模型**）：前置参数校验/路径守卫/权限/备份/循环检测；后置**写后自检**（读回验证完整性）+ 结果规范化。拦截后动作：修正重试 1 次 → 仍失败报告用户。**安全底线不允许模型自检**。
**落地**：`src/guard/`（validate.rs / post_check.rs）；权限网关（09）为其前置校验主体。详见 `modules/10-工具层.md` §十三。

## 决策 33：能力分层与本地/云端对接（2026-10-22 重写）

**结论**：边界按**认知复杂度**分档，而不是按"步骤多少"——编排复杂（多步/多文件）由本地 Planner 代码拼接完成；认知复杂（长上下文理解/深度推理/高质量写作）默认对接云端。
- **三档 grade**：`local`（永不出网）/ `localFirst`（本地先试、失败升级）/ `cloud`（默认上云，不再让本地先撞墙）。
- **判定优先级**：用户「仅本地」开关（默认开启）> 静态能力白名单（`config/capabilities.json`）> 确定性信号（文件数 ≥2 或输入 >8000 字符升一档）> **模型自评不参与**。
- **profile 机制**：`small`（轻量档（small），复杂任务上云）/ `large`（14B+，本地承担更多）；切换判据＝硬件基准 + 任务基准双达标。
- **云端交互**：「仅本地」开启 → 需云端时每次弹窗放权；关闭 → 本地确定性抽取后直接上云不弹窗，但保留强提示、状态栏标识、审计条目、**会话云端预算上限（默认 50k tokens，超额自动降级本地）**。
- **隐私红线**：敏感源（`secrets.json` / `.env*` / `.ssh` / `.aws` / `*.key|pem|p12|pfx` / `id_rsa` 等）与密钥形态（`sk-` / PEM / `AKIA` / `ghp_` / `xox` / `AIza`）**即使开关关闭、即使有导出授权也绝不上云**；程序**不得代为复制**，只提供查看方法，由用户自行复制；两层防护＝来源标记（可靠层）+ 形态检测（兜底层）。
- **本地初步处理**＝确定性抽取（文件树/符号表/grep 命中/代码块/标题层级），**不是**让 7B 先摘要。
**理由**：阶段 2 实测多步链 100% 失败已由 Planner/Guard 解决（编排复杂 ≠ 认知复杂）；轻量档（small） 的认知上限无法靠编排弥补，先撞墙再上云既慢又脏。
