# 31 · 角色知识库与学习流水线

> 状态：已定稿，待实现。安全细节见 `32-知识库安全与审计.md`。

## 1. 目标

每个角色拥有独立的自学习知识库，形成闭环：

```
外部采集一次 → 摘要 → 本地嵌入 → 落库
                ↓
        本地检索 → 本地模型回答（带引用）
```

原则：**外部只用于采集，问答全部本地**，以降低调用成本与隐私风险。

## 2. 目录结构

```
data/kb/<roleId>/
  chunks.jsonl      # 分块（正文 + 摘要 + 嵌入）
  sources.jsonl     # 来源（URL、标题、评级、条目数、花费）
data/memory/<roleId>.jsonl   # 角色记忆（会话摘要）
data/memory/shared.jsonl     # 公用记忆（仅管家可写，需授权）
data/audit/<roleId>/YYYY-MM.jsonl
```

角色与库一一对应：

| 角色 id | 显示名 | 库 |
|---|---|---|
| `dev` | 嵌入式高手（原「代码助手」改名，id 不变） | `kb/dev` |
| `health` | 健康管家 | `kb/health` |
| `mind` | 心灵伙伴 | `kb/mind` |
| `butler` | 管家 | `kb/butler` |

## 4. 入库流水线

```
校验 URL（安全见 32） → 抓取（UA/超时 15s/最多 5 跳重定向）
  → 朴素提取正文（保留 <pre>/<code>，h1–h4 转 markdown 标题）
  → 归一化 + 计算 hash（已存在则跳过）
  → 分块（段落聚合 800–1200 字）
  → 整篇一次摘要（外部模型，含分块清单）
  → 关键词重叠度标注 isKey（不超过分块数 30%）
  → 本地嵌入（nomic-embed-text，串行，失败重试 1 次）
  → 追加写 chunks.jsonl / sources.jsonl
  → 写审计 + 记账（摘要花费）
```

### 4.1 提取规则（朴素）

- 去除 `<script>` / `<style>` / `<nav>` / `<footer>`
- `<pre>`、`<code>` 内容原样保留并加 markdown 代码块标记
- `h1`–`h4` 转为 `#`～`####`
- 合并连续空白，保留段落分隔

### 4.2 分块规则

- 按段落聚合，目标 800–1200 字，超长段落按句号切分
- 保留所属标题作为分块前缀，便于检索定位
- 单篇最多 60 个分块，超出截断并标 `truncated: true`

### 4.3 摘要与关键分块

- 整篇一次摘要（省请求、省钱）
- 摘要生成后，用关键词重叠度与各分块比对，重叠高的标 `isKey: true`
- `isKey` 数量上限为分块数的 30%，防止全部标关键

## 5. 检索与回答

```
提问 → 该角色库向量检索 top-5（余弦阈值 0.50）
    → 命中：编号 [1]…[n]，拼进系统提示
    → 未命中：回答“库里没有，需要入库吗？”
```

规则：

- 检索优先返回 `isKey` 分块，其次按相似度
- `embeddingStatus = "failed"` 的分块不参与向量检索，但参与关键词兜底检索
- 回答要求模型内联引用 `[n]`，末尾附来源列表：

```
根据 [1] 所述…… [2] 提到……

来源：
[1] https://…/interrupt-handling.html（trusted）
[2] https://…/rtos-basics.html（neutral，仅供参考）
```

- 来源 `neutral` 标注“非权威，仅供参考”；低置信度记忆不参与编号

## 6. 记忆机制

### 6.1 角色记忆

- 触发：每 5 轮对话 + 会话结束时生成一条摘要
- 上限：单角色 300 条；相似度 > 0.85 的条目合并（保留最新表述，confidence 取高，更新 lastUsedTs）
- 失败：记 `summaryStatus: "failed"`，下次会话开始时重试，最多 3 次

### 6.2 公用记忆

- 内容：偏好、习惯、长期目标、称呼
- 写入：**仅管家**，且需弹窗授权（一次性 / 会话授权）
- 上限：200 条，按 LRU（`lastUsedTs`）淘汰
- 字段含 `confidence: high | medium | low`，low 在回答中标注“可能不准确”

## 7. 规模与上限

| 指标 | 阈值 | 行为 |
|---|---|---|
| 单库分块 | 2000 | 告警（日志 + 界面提示） |
| 单库分块 | 5000 | 拒绝写入，提示先清理或归档 |
| 单次入库来源 | 20 | 超出拒绝 |
| 单篇分块 | 60 | 截断并标记 |

## 8. 角色权限

| 角色 | 私有库 | 公用记忆 | 其他目录 |
|---|---|---|---|
| 嵌入式高手 | 读写（免授权） | 读 | 读文件；写需授权 |
| 健康管家 | 读写（免授权） | 读 | 无 |
| 心灵伙伴 | 读写（免授权） | 读 | 无 |
| 管家 | 读写（免授权） | **写（需授权）** | 读；写需授权（限 `data/notes/`） |

## 9. 实现顺序

1. 数据层：`kb` / `memory` 读写与上限校验
2. 入库流水线（抓取 → 提取 → 摘要 → 嵌入 → 落库）
3. 角色页「学习」入口（粘贴链接、进度、条目列表）
4. 检索 + 引用接入问答
5. 记忆摘要（5 轮 / 会话结束）
6. 管家写授权弹窗

## 11. 评审后定稿（v2）

以下为与外部评审对齐后的最终决定，优先于上文冲突处。

### 11.1 提取与摘要

- 朴素提取保留 `<pre>` / `<code>`，**表格转 markdown**
- 提取后文本 < 原文 30% 标 `extractQuality: low`，待确认卡片提示
- 摘要：整篇一次；**单篇 > 2 万字按章节标题分两段**（无标题按段落），合并时注明“分两部分摘要”
- 摘要模型固定使用**便宜档**

### 11.2 关键分块

`isKey` 不再用关键词重叠，改为**分块嵌入与整篇摘要嵌入的余弦相似度**，取前 30%。

### 11.3 引用校验（三级）

1. 编号越界 → 廉价重编号（不重生成全文）
2. 句子与该分块词重叠率 < **0.15** 判为张冠李戴 → 替换为重叠率最高且 > **0.30** 的编号
3. 无法修复 → 整体重生成（≤ 2 次）→ 仍失败则末尾标注“引用可能不准确”

### 11.4 来源评级

- **可见两级**：权威（trusted）/ 普通
- **黑名单静默生效**：命中即丢弃，卡片显示“来源被屏蔽”，不暴露规则
- 待确认列表底部：「本次 N 个来源被屏蔽」，可展开看域名（不显示具体 URL）

### 11.5 学习控制

- 三种触发：给链接 / 给主题 / 计划（计划 **24 小时未开始即失效**；每个主题完成即暂停等确认）
- 待确认持久化：`data/kb/<roleId>/pending.jsonl`，三态：待确认 / 已入库 / 已丢弃
- **每日学习预算做成可配置变量**（`settings.learnDailyBudget`，默认 ¥2.00）：
  - 首次学习可临时调高，日常可调低
  - 用到 70% 时提示；超限拒绝并提示，不自动降级
- 单次 ≤ 20 来源，单篇 ≤ 60 分块

### 11.6 回滚

按 **URL** 删除该来源全部分块 + `sources.jsonl` 对应条目；`batchId` 仅用于审计；回滚为终态操作，二次确认。

### 11.7 库内搜索（本轮做）

- 关键词 + 子串匹配，范围：标题 / 摘要 / 原文
- 加权：**标题 3、摘要 2、原文 1**，按加权得分排序取 top-20
- 展示：命中片段 + 来源标题 + URL，可展开上下文
- 不走向量、零外部调用、可离线

### 11.8 公用记忆

最近 **100 条**（超出丢弃最旧），保留 `lastUsedTs` 备用；仅管家可写且需授权；低置信度不参与引用编号。

### 11.9 规模

单库 2000 条告警；5000 条硬停仅留接口，本轮不实现。

### 11.10 实现顺序

1. 阶段 1 与阶段 2 **并行**：库内搜索（假数据验证）／抓取→待确认→摘要→落库（先定 schema）
2. 阶段 3：检索 → 回答 → 引用校验
3. 阶段 4：学习控制（预算/黑名单/回滚/计划）
4. 阶段 5：记忆系统
