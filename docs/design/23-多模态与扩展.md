# 23 - 多模态与扩展

> 状态：已定稿 | 最后更新：2026-01-15 | 关联：02-架构设计.md、03-权限模型.md、04-数据边界.md、22-安全模型.md

## 一、概述

ai-assistant 作为本地多 Agent 协作系统，需要支持**多模态输入理解**和**可扩展的能力边界**。本文档定义：

- 多模态数据的处理流程与安全策略
- 工具/角色/知识库的扩展机制
- 外部系统集成方式
- 前端扩展能力（Tauri 插件）

**核心原则**：
- 多模态处理**默认本地优先**，涉及云端时询问用户（决策 18）
- 扩展机制**不破坏安全边界**，新增工具/角色仍需通过权限网关
- 所有扩展**可审计、可回滚**

## 二、多模态能力

### 2.1 图片理解（决策 18）

**当前阶段（0-2）：纯文本为主，图片通过外部多模态模型处理**

| 场景 | 处理方式 |
|------|---------|
| 用户发送图片 | 询问用户："传云端分析还是跳过？" |
| 用户选择"传云端" | 上传到用户配置的云端多模态 API（OpenAI 兼容接口，平台名+Key，见 `ops/12-模型部署.md` §云端兜底），返回文本描述后注入上下文 |
| 用户选择"跳过" | 忽略图片，提示用户用文字描述 |
| 用户选择"本地处理" | 若本地部署了多模态模型（如 LLaVA），直接调用；否则提示不可用 |

**处理流程**：
用户发送图片
│
▼
┌─────────────────────────┐
│ 多模态网关 │
│ · 检查本地是否有多模态模型 │
│ · 检查用户偏好设置 │
└─────────┬───────────────┘
▼
┌──────────┐
│ 有本地模型？│
└────┬─────┘
│是
▼
┌──────────┐
│ 本地推理 │ → 文本描述 → 注入上下文
└──────────┘
│否
▼
┌──────────┐
│ 询问用户 │ "传云端分析还是跳过？"
└────┬─────┘
│
├─ 传云端 → 上传到云端 API → 返回文本描述 → 注入上下文
│ （记录审计日志：时间戳、图片hash、目标API）
│
└─ 跳过 → 忽略，提示用户用文字描述
纯文本
**安全约束**：
- 图片上传前**不保留本地副本**（除非用户显式保存）
- 云端 API 返回的文本内容经过 Prompt 注入检测（见 `22-安全模型.md` §5.1）
- 图片中若含敏感信息（如代码截图），用户自行承担风险（已告知）

### 2.2 音频/语音（阶段 3+ 规划）

| 能力 | 说明 | 优先级 |
|------|------|--------|
| 语音输入 | 本地 STT（如 Whisper.cpp）→ 文本 → 正常处理 | 中 |
| 语音输出 | 文本 → 本地 TTS → 语音播放 | 低 |
| 音频文件分析 | 用户上传音频 → 转写 → 注入上下文 | 低 |

**约束**：语音数据默认本地处理，不上传云端（除非用户配置云端 STT）。

### 2.3 未来扩展：视频/PDF/Office

| 类型 | 处理方式 |
|------|---------|
| 视频 | 抽帧 → 逐帧图片理解 → 汇总 |
| PDF | 文本提取（本地 pdf-extract）→ 注入；扫描件 → 图片理解 |
| Office | 文本提取 → 注入 |

## 三、扩展机制

### 3.1 工具扩展

**当前设计**：工具集按 Agent 类型固定绑定（决策 7），不支持运行时动态加载新工具。

**扩展方式（阶段 2+）**：

1. **内置工具清单**：`src/tools/builtin/` 下预置工具
2. **新增工具流程**：
   - 开发者编写工具实现（Rust，实现 `Tool` trait）
   - 在 `src/tools/registry.rs` 中注册
   - 在角色 YAML 的 `allowed_tools` 中添加工具名
   - 重新编译
3. **工具权限声明**：每个工具声明自身默认权限级别（L0-L3）
4. **安全审查**：新工具必须经过权限网关集成测试
rust
// 伪代码：工具 trait
trait Tool {
fn name(&self) -> &str;
fn description(&self) -> &str;
fn default_permission(&self) -> PermissionLevel; // L0-L3
async fn execute(&self, params: Value) -> Result<ToolResult>;
}
纯文本
### 3.2 角色扩展

**用户自定义角色**：

1. 在 `AI_ASSISTANT_DATA/roles/` 下创建 YAML 文件
2. 定义角色属性：
yaml
AI_ASSISTANT_DATA/roles/my-custom-role.yaml
role:
name: my-custom-role
display_name: "我的自定义角色"
description: "专门用于XX任务的角色"
max_permission: L2
allowed_tools:
•
read_file
•
write_file
•
grep
knowledge_domains:
•
custom_role
system_prompt: |
你是一个专注于XX的助手...
model_preference:
coordinator: qwen25-7b
sub_agent: qwen25-3b
纯文本
3. 主协调者启动时扫描并加载自定义角色
4. 用户可通过对话切换角色：`/role my-custom-role`

**角色优先级**：内置角色（`src/roles/builtin/`）> 自定义角色（`data/roles/`）

### 3.3 知识库扩展

| 扩展方式 | 说明 | 触发者 |
|---------|------|--------|
| 手动添加 | 用户直接编辑 JSON 文件或通过 UI 表单 | 用户 |
| Agent 建议 | Agent 在对话中发现知识缺口，建议添加 | 主协调者 |
| 自动积累 | 从对话中提取事实，标记为 `source: agent` | 主协调者 |
| 链接抓取 | 用户提供 URL，系统抓取并总结为知识条目 | 用户/主协调者 |
| 外部导入 | 从其他工具/格式导入（见 `19-数据迁移.md`） | 用户 |

**知识文件格式**（结构化 JSON）：
json
{
"schema_version": "1.0",
"id": "unique-knowledge-id",
"title": "知识条目标题",
"content": "知识内容（支持 Markdown）",
"source": "manual",
"tags": ["rust", "async"],
"created_at": "2026-01-15T10:00:00+08:00",
"updated_at": null
}
纯文本
### 3.4 前端扩展（Tauri 插件）

**当前**：纯 HTML + CSS + JS，Tauri v1 封装（决策 20）

**扩展方式**：
- 新增 Tauri 命令（Rust 后端暴露新 API）
- 前端通过 `invoke()` 调用
- 插件机制（Tauri Plugin）：阶段 3+ 支持第三方插件
typescript
// 前端调用示例
import { invoke } from '@tauri-apps/api/tauri';
const result = await invoke('analyze_image', {
imagePath: '/path/to/image.png',
mode: 'cloud'
});
纯文本
## 四、外部系统集成

### 4.1 链接自主学习

用户给链接 → AI 自主学习（决策 16）：
用户提供 URL
│
▼
网络策略检查（域名白名单/询问）
│
▼
抓取内容（存 cache/external/）
│
▼
主协调者总结为知识条目
│
▼
询问用户：保存到知识库？[是/否/编辑后保存]
│
├─ 是 → 写入 knowledge/{domain}/ 或用户指定位置
├─ 否 → 仅本次使用，不保存
└─ 编辑后保存 → 用户修改 → 保存
纯文本
**约束**：
- 外网访问需询问（除非域名在白名单，决策 17）
- 抓取频率限制：同一域名 1 分钟内不超过 5 次
- 抓取内容缓存：`cache/external/{url_hash}.json`，可配置过期时间

### 4.2 API 集成（阶段 3+）

| 集成类型 | 用途 | 安全约束 |
|---------|------|---------|
| 云端模型 API | 8B 不可用时的兜底 | 只发送脱敏描述（决策 27） |
| 搜索 API | 实时信息检索 | 用户配置 API Key，不硬编码 |
| 代码仓库 API | GitHub/GitLab 集成 | Token 存 `config/secrets.json`，不暴露给 Agent |
| 文档站 API | 自动抓取文档 | 受域名策略约束 |

### 4.3 Git 集成（决策 23）

- 使用 Git 命令行调用（非 libgit2）
- Agent 可执行：`git status`、`git diff`、`git log`、`git commit`
- 禁止 Agent 执行：`git push`、`git remote add`
- 用户明确"有时候可以直接让它帮我提交" → `git commit` 允许（L2 需确认）

## 五、扩展的安全约束

所有扩展必须遵守：

| 约束 | 说明 |
|------|------|
| 权限网关 | 扩展工具必须注册到权限网关，声明权限级别 |
| 数据边界 | 扩展不得绕过数据边界（如直接读取 memory/） |
| 审计日志 | 扩展操作记录到审计日志 |
| 回滚支持 | 扩展产生的数据变更必须可回滚 |
| 签名验证 | 阶段 4+ 要求第三方扩展签名 |
