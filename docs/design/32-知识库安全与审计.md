# 32 · 知识库安全与审计

> 配套 `31-角色知识库与学习流水线.md`。本文只管“怎么不出事”，不管功能。

## 1. 写入路径约束

角色对自己的 `data/kb/<roleId>/` 有免授权写权限，但必须满足：

1. **解析后校验**：写入前对目标路径做 `canonicalize`（Windows 下等价 `realpath`），确认其前缀为 `data/kb/<roleId>/`
   - 仅检查字符串不够：`data/kb/dev/../butler/` 解析后越界
2. **禁止符号链接/目录联接**：`data/kb` 下出现 symlink 或 junction 一律拒绝
3. **文件名白名单**：只允许 `chunks.jsonl`、`sources.jsonl` 与临时文件 `*.tmp`
4. **追加写**：`O_APPEND | O_CREAT`，先写 `.tmp` 再 rename，避免半条记录
5. **权限说明**：POSIX `0640` 在 Windows 不适用，本工程按“同一用户”假设，安全边界由应用层保证

## 2. 抓取安全（SSRF）

用户可输入任意 URL，必须防护：

1. **协议限制**：只允许 `http` / `https`，拒绝 `file:`、`ftp:`、`data:` 等
2. **DNS 解析后校验**：解析目标域名得到 IP，再判断是否属于内网段
   - 拒绝：`127.0.0.0/8`、`10/8`、`172.16/12`、`192.168/16`、`169.254/16`、`::1`、`fc00::/7`
3. **重定向逐跳校验**：每一跳都要重新解析 + 校验，最多 5 跳
4. **动态 DNS 拒绝**：`nip.io`、`sslip.io` 等可解析到内网的服务直接拒绝
5. **超时与体积上限**：连接 10s、总时长 30s、响应体上限 5MB，超出即中止

## 3. URL 规范化

用于去重与哈希，顺序如下：

1. 统一小写协议与主机名
2. 去掉 `#fragment`
3. 去掉跟踪参数：`utm_*`、`fbclid`、`gclid`、`ref`、`source`
4. 去掉末尾多余的 `/`（根路径除外）
5. **以重定向后的最终 URL 为准**计算哈希；原始 URL 仅用于展示

## 4. 来源分级（三级）

| 级别 | 定义 | 行为 |
|---|---|---|
| `trusted` | 命中白名单（WHO、NHS、CDC、政府卫生机构、官方文档站点） | 正常引用，标注来源名 |
| `neutral` | 非白名单但内容合规 | 入库，回答时标注“来源非权威，仅供参考” |
| `blocked` | 命中黑名单（伪医学、广告、内容农场） | **抓取后、摘要前**丢弃，不花钱 |

- 规则文件：`config/source-rules.json`（白名单、黑名单、关键词规则）
- 评级结果写入 `sources.jsonl`，允许手动纠正
- 健康 / 心理两个库优先引用 `trusted`

## 5. 嵌入与数据

1. **量化存储**：int8 + 每向量缩放系数，落盘省 75%；检索时转回 f32
2. **模型版本**：每条记录 `embeddingModel` 与维度，换模型时可识别需重算的分块
3. **失败兜底**：`embeddingStatus = "failed"` 的分块不参与向量检索，参与关键词检索
4. **重算任务**：换嵌入模型后提供“重建索引”（后续版本）

## 6. 审计

### 6.1 位置与格式

```
data/audit/<roleId>/YYYY-MM.jsonl
```

每行：

```json
{
  "ts": 1793000000000,
  "role": "dev",
  "action": "write | read | delete | ingest",
  "sourceUrl": "https://…",
  "chunkCount": 12,
  "durationMs": 1840,
  "cost": 0.0012,
  "result": "success | failed",
  "error": ""
}
```

### 6.2 记录范围

- 入库（含花费）
- 检索（只记条数与命中数，不记内容）
- 删除/归档
- 越权尝试（路径越界、被拒 URL）——**必须记**

## 7. 并发与幂等

1. **单写者队列**：进程内每个库一个写入队列，串行 append
2. **实例锁**：`data/kb/.lock` 写 PID，启动时若锁存在且进程存活则提示
3. **幂等**：写入前查 `hash`（启动时载入内存 Set），已存在直接跳过
4. **批内去重**：同一批多个链接指向同一最终 URL 时只处理一次

## 8. 隐私红线（与既有约束一致）

- 本地信息（对话、健康数据、笔记）**不得**随抓取或摘要请求外发
- 摘要请求只包含被抓取的公开网页正文
- 敏感路径（`secrets.json`、`.env`、`.ssh`）仍受既有红线保护

## 9. 检查清单（实现时逐条验证）

- [ ] 路径越界（`../`）被拒
- [ ] 软链接指向外部被拒
- [ ] `file://` 与内网地址被拒
- [ ] 重定向到内网被拒
- [ ] 同 URL 重复入库被跳过
- [ ] 同内容不同 URL 被跳过
- [ ] 超 5000 条拒绝写入
- [ ] 审计文件按月分片且包含越权记录
- [ ] 摘要请求体不含本地数据

## 10. 评审后补充（v2）

### 10.1 黑名单审计

- 命中黑名单时写审计：`action: "blocked"`，含域名、URL、时间、命中规则标识
- 卡片仅显示“来源被屏蔽”，**不暴露具体规则**
- 待确认列表底部汇总「本次 N 个来源被屏蔽」，展开仅显示域名

### 10.2 预算与越权

- 超预算被拒绝的入库请求同样写审计：`action: "rejected"`，含预估花费与当日已用
- 路径越界、被拒 URL（SSRF）必须记 `action: "denied"`

### 10.3 引用校验审计

- 引用重编号、替换、重生成各记一条轻量审计（不含正文），便于统计“引用质量”
