# 27 - 性能优化（含显存/资源调度权威模型）

> 状态：已定稿 | 最后更新：2026-01-15 | 关联：02-架构设计.md、05-失败处理.md、14-开发环境.md、20-运行环境适配.md、25-测试策略.md
> 本文档是**资源调度（显存/内存/并发）的唯一权威**。02/05/07/14/20/25 等文档涉及调度处均以本文档为准。

## 一、概述

ai-assistant 运行在用户本地机器上，目标硬件为 **i5-10400F + RTX 2070 8GB + 16GB RAM**。本文档定义系统各层面的性能优化策略，重点是**一套不打架的显存调度模型**。

**优化目标**：

| 指标 | 目标值 | 说明 |
|------|--------|------|
| 路由响应 | < 500ms | 3B 模型推理 + 分发 |
| 主协调者首 token | < 2s | 7B 模型冷启动/首次生成 |
| 子 Agent 唤醒 | < 1s | 3B 模型加载（若未常驻） |
| 工具调用延迟 | < 200ms（本地） | 不含模型推理时间 |
| 前端帧率 | ≥ 60fps | 滚动、展开/折叠等操作 |
| 总显存占用 | < 6.5GB | 预留 ~1.5GB 给系统/桌面/CUDA |
| 内存占用 | < 4GB（Rust 进程） | 不含模型显存 |

**核心原则**：
- 本地优先，减少网络往返
- 按需加载，不预占资源
- 写前备份异步化，不阻塞主流程
- 上下文管理主动触发，避免被动溢出

## 二、显存与内存调度（权威模型）

### 2.1 硬件约束

| 组件 | 规格 | 可用资源 |
|------|------|---------|
| GPU | RTX 2070 8GB GDDR6 | **~6.5GB 可用**（系统/桌面/CUDA 预留 ~1.5GB） |
| CPU | i5-10400F | 6 核 12 线程（推理瓶颈在显存不在 CPU） |
| 内存 | 16GB DDR4 | ~12GB 可用（系统占用 ~4GB） |

### 2.2 模型显存估算（统一值，实测可能有 ±0.5GB 浮动）

| 模型 | 精度 | 显存占用 | 用途 |
|------|------|---------|------|
| Qwen2.5-3B | Q4_K_M | **~2.5GB** | 路由层 / 轻活子 Agent |
| Qwen2.5-7B | Q4_K_M | **~5.0GB** | 主协调者 / 重活子 Agent |

> 其它文档（05/12/14/20 等）如出现不同数字，一律以本节为准。

### 2.3 调度模型（唯一方案）

**结论：8GB 显存装不下「3B + 7B + 多子 Agent」全常驻**，方案如下：

| 角色 | 模型 | 驻留方式 | 显存 |
|------|------|---------|------|
| 路由层 | 3B | **GPU 常驻**（Ollama `keep_alive=10m` 保持加载） | ~2.5GB |
| 主协调者 | 7B | **内存常驻 + GPU 分层按需 offload**（Ollama `num_gpu` 控制 GPU 层数，保证 GPU 余量 ≥ 1.5GB 给子 Agent） | GPU ≤ ~4GB（其余层在 CPU 内存） |
| 子 Agent 3B | 3B | 按需加载，第 1 个进 GPU（~2.5GB），**第 2 个走 CPU 推理** | GPU 2.5 / CPU 并行 |
| 子 Agent 7B | 7B | **不进 GPU**：走 CPU 推理或云端兜底 | 0（本地 GPU） |

**并发上限**：
- 3B 子 Agent 并发上限 **2**（第 1 个 GPU、第 2 个 CPU）；第 3 个排队（最多 30s）→ 超时降级：串行化 / 云端 / 报告用户
- 7B 子 Agent 并发上限 1（CPU 或云端），与主协调者共享模型实例时需排队
- 显存余量 < 1.5GB 时，拒绝新的 GPU 模型加载

**内存保护**：系统内存使用 > 14GB（16GB 的 87.5%）时拒绝新的子 Agent 派发，触发清理（工作区、过期缓存）。

**降级矩阵**：

| 条件 | 降级动作 |
|------|---------|
| 显存不足 | 子 Agent 走 CPU 推理 / 云端 |
| 内存不足 | 减少上下文窗口（8K→4K）、串行化任务 |
| 磁盘空间 < 1GB | 暂停备份、清理旧日志 |
| 无 GPU / 显存 < 4GB | 全部 CPU 推理，并发上限降为 1 |
| CPU 温度 > 85°C | 降低并发数 |

### 2.4 Ollama 配置（统一）

```json
{
  "num_parallel": 2,
  "num_ctx": 8192,
  "num_gpu": 1,
  "main_gpu": 0
}
```

环境变量：`OLLAMA_CONTEXT_LENGTH=8192`、`OLLAMA_KEEP_ALIVE=10m`。
**勿设 `keep_alive=-1`** 永久常驻，16GB 内存偏紧；运行 agent 时建议关掉多余浏览器标签。

## 三、推理参数与 KV Cache

### 3.1 推理参数调优

| 参数 | 路由层 | 主协调者 | 子 Agent |
|------|--------|---------|---------|
| temperature | 0.1（确定性） | 0.3（平衡） | 0.2（任务导向） |
| top_p | 0.9 | 0.95 | 0.9 |
| num_predict | 256（短输出） | 2048（长输出） | 1024 |
| repeat_penalty | 1.1 | 1.1 | 1.1 |
| num_ctx | 4096 | 8192 | 4096 |

### 3.2 KV Cache 复用

- 主协调者常驻实例复用 KV Cache（同一会话内）
- 角色切换时，上下文存角色缓存池（`cache/role_contexts/`），切换回来后恢复 KV Cache
- 子 Agent 完成后释放 KV Cache

## 四、上下文与 Token 管理

### 4.1 Token 硬上限与分段（决策 8）

| 角色 | 硬上限 | 超限处理 |
|------|--------|---------|
| 3B 路由 | 4K | 截断早期消息，保留最近 2K + 系统提示 |
| 7B 主协调者 | 8K | 分段处理：先摘要前半部分，再处理后半部分 |
| 3B 子 Agent | 4K | 截断，报告主协调者 |
| 7B 子 Agent（重活） | 8K | 按文件分段 + 增量 diff |

### 4.2 上下文外移与摘要压缩

**触发条件**：Token 使用量达 70% → 外移非关键数据到指针；达 90% → 强制摘要压缩。

**外移策略**：
- 工具调用结果（长输出）→ 存 `workspace/{task_id}/tool_outputs/` → 上下文只保留指针
- 早期对话轮次 → 摘要后替换原文
- 知识库检索结果 → 只保留引用 ID，内容按需加载

**摘要压缩**：标记关键决策点（用户指令、Agent 决策、写操作）→ 非关键轮次用 3B 快速摘要 → 替换原文保留关键轮次完整 → 压缩后 token 数应下降 >30%。

### 4.3 8K 超限分段处理（增量 diff）

跨文件重构超过 8K 时：按文件拆分任务 → 每个子 Agent 处理单个文件（≤4K）→ 主协调者汇总 diff 生成增量补丁 → 用户确认后应用。

## 五、工具调用优化

### 5.1 写前备份异步化

写操作：主线程执行写入，后台线程复制原文件到 `backups/`（异步不阻塞）。备份失败不影响写操作但记录警告；备份文件可用硬链接（NTFS）减少复制时间。

### 5.2 文件锁（统一约定，见 05-失败处理.md §2）

- 锁目录：`AI_ASSISTANT_DATA/workspace/.locks/{file_path_hash}.lock.json`
- 锁超时：**5 分钟**自动释放（防死锁）
- 读写锁分离：读操作不阻塞其他读

### 5.3 并行工具调用

- 独立工具调用可并行执行（如多个 `read_file`）
- 依赖顺序的工具调用串行执行
- 主协调者决策时标记工具依赖关系

### 5.4 工具结果缓存

| 工具 | 缓存策略 |
|------|---------|
| read_file | 文件未修改时返回缓存（mtime 检查） |
| grep | 同目录同模式 5min 内缓存 |
| git_status | 30s 内缓存 |
| web_fetch | 按 URL 缓存到 `cache/external/`，可配置过期 |

## 六、并发与调度

### 6.1 任务队列

用户请求 → 任务队列（最大并发 3）→ 主协调者（常驻，拆解/派发）→ 子 Agent 池（3B 最大 2 并发，第 2 个走 CPU）。

### 6.2 优先级调度

| 优先级 | 类型 | 说明 |
|--------|------|------|
| 高 | 用户直接消息 | 立即处理 |
| 中 | 主协调者派发的子任务 | 正常排队 |
| 低 | 后台任务（知识整理、孤儿清理） | 空闲时执行 |

### 6.3 孤儿清理

后台定时任务每 24h 扫描 `workspace/` 删除超过 24h 未更新的任务目录；启动时检查并清理。

## 七、缓存策略

### 7.1 链接缓存

- 位置：`AI_ASSISTANT_DATA/cache/external/{url_hash}.json`
- 过期策略：默认 7 天，可配置
- 同一域名 1min 内不超过 5 次请求

### 7.2 模型响应缓存（阶段 3+）

- 相同 prompt（hash 匹配）→ 返回缓存响应
- 仅对确定性输出（temperature=0）缓存
- 缓存位置：`cache/model_responses/`，模型更新后自动失效

### 7.3 知识检索缓存

- 检索结果缓存：相同查询 10min 内直接返回
- 知识库更新时自动失效相关缓存

## 八、前端性能

- 虚拟列表：对话历史超过 100 条时启用
- 代码块懒高亮：滚动到视口才渲染
- CSS 动画用 `transform`/`opacity`（GPU 加速）；批量 DOM 更新（requestAnimationFrame）
- 流式输出逐块追加，节流每 16ms 最多一次；长消息（>500 字）分段渲染
- 无外部 CDN，CSS/JS 内联合并；系统字体
- 对话历史 > 500 条自动卸载非当前任务消息（保留摘要）；图片预览用 `URL.createObjectURL` 并 `revokeObjectURL`

## 九、磁盘 I/O 优化

| 操作 | 优化方式 |
|------|---------|
| 日志写入 | 异步追加，批量刷盘（每 100ms 或 1KB） |
| 配置读取 | 启动时加载到内存，运行中只写不读 |
| 知识库 JSON | 按需加载单个文件，不全量读取 |
| 备份文件 | 使用硬链接（NTFS），减少复制开销 |
| 数据库（阶段 4+） | 使用 SQLite WAL 模式 |
