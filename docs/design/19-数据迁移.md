# 19 - 数据迁移

> 状态：已定稿 | 最后更新：2026-01-15 | 关联：21-更新与回滚.md、03-权限模型.md、08-记忆与知识.md、ops/13-Cline集成.md

## 一、概述

数据迁移指在以下场景中，将 `AI_ASSISTANT_DATA/` 下的数据从一个格式/版本/来源转换为新格式/版本/目标：

| 场景 | 触发条件 | 示例 |
|------|---------|------|
| **版本升级** | 程序版本更新导致数据格式变化 | v0.1 配置为 TOML → v0.2 改为 JSON |
| **格式变更** | 知识/记忆/配置的 JSON schema 演进 | 知识文件新增 `source` 字段 |
| **外部工具导入** | 从其他 AI 工具迁移数据到本系统 | 从 Cline / Copilot / AutoGPT 导入历史对话、记忆 |
| **数据修复** | 检测到数据损坏或不一致 | 手动修复后重新导入 |
| **环境迁移** | 更换电脑或重装系统 | 从备份恢复全部数据 |

**核心原则**：
- 迁移前自动备份（写前备份，决策 6，详见 `21-更新与回滚.md`）
- 迁移可回滚（回滚到迁移前状态）
- 迁移过程幂等（重复执行不破坏数据）
- 用户可审计（生成迁移报告）

## 二、版本化数据格式

### 2.1 配置文件版本

`app.json` 中包含 `schema_version` 字段：
json
{
"_comment": "ai-assistant 主配置文件",
"schema_version": "1.0",
"version": "0.1.0",
"data_root": "{程序目录}/data/"
}
纯文本
当程序启动时检测到 `schema_version` 低于当前期望版本，触发迁移流程。

### 2.2 知识文件版本

知识库 JSON 文件包含 `schema_version`：
json
{
"schema_version": "1.0",
"id": "rust-borrow-checker",
"title": "Rust 借用检查器",
"content": "...",
"source": "manual",
"created_at": "2026-01-15T10:00:00+08:00"
}
纯文本
### 2.3 记忆文件版本

记忆 JSON 文件同样包含 `schema_version`。

### 3.1 迁移计划内容
json
{
"migration_id": "mig_20260115_001",
"from_version": "0.9",
"to_version": "1.0",
"files": [
{
"path": "config/app.json",
"action": "upgrade_schema",
"backup_path": "backups/migration_20260115_001/config/app.json"
},
{
"path": "knowledge/dev/rust-traits.json",
"action": "add_field:source",
"backup_path": "backups/migration_20260115_001/knowledge/dev/rust-traits.json"
}
],
"estimated_time": "5s"
}
纯文本
### 3.2 迁移执行规则

| 规则 | 说明 |
|------|------|
| 按依赖顺序迁移 | 先配置 → 再知识库 → 再记忆 → 最后工作区 |
| 逐文件原子迁移 | 每个文件迁移成功后才处理下一个，失败则停止 |
| 失败处理 | 停止迁移 → 回滚已迁移的文件 → 报告用户 |
| 幂等性 | 重复执行迁移脚本不会重复修改已迁移的文件 |

## 四、具体迁移场景

### 4.1 配置格式变更（TOML → JSON）

如果早期版本使用 TOML，升级到 v0.1 后改为 JSON：

1. 读取旧 `config/app.toml`
2. 转换为等价 JSON 结构
3. 写入 `config/app.json`
4. 备份旧 TOML 到 `backups/migration_*/config/app.toml`
5. 旧 TOML 可保留或删除（用户选择）

### 4.2 知识库字段新增

从 v0.1 到 v0.2，知识文件新增 `source` 字段：

- 旧文件无 `source` → 迁移时自动添加 `"source": "legacy"` 或询问用户
- 旧文件有 `source` → 保持不变

### 4.3 记忆分层重构

从单文件记忆改为分层目录结构：
旧结构：memory.json
新结构：memory/
├── shared/
│ └── common.json
├── dev/
│ └── preferences.json
└── general/
└── habits.json
纯文本
迁移步骤：
1. 解析旧 `memory.json`
2. 按类别分类条目
3. 写入对应分层文件
4. 备份旧文件

### 4.4 外部工具导入

#### 从 Cline 导入

Cline 数据存储位置：`~/.cline/` 或 VS Code 扩展数据目录。

导入内容：
- 对话历史 → 转换为记忆（标记 `source: import/cline`）
- 自定义指令 → 转换为角色 YAML 或知识库
- 设置 → 映射到 `config/app.json`

导入流程：
1. 用户指定 Cline 数据目录路径
2. 扫描并解析 Cline 数据文件
3. 预览导入内容（用户确认）
4. 执行导入（写入 `AI_ASSISTANT_DATA/`）
5. 生成导入报告

#### 从其他工具导入

| 工具 | 可导入数据 | 目标位置 |
|------|-----------|---------|
| GitHub Copilot | 无本地数据（云端） | 不可导入 |
| AutoGPT | 任务历史、记忆 | 记忆 + 知识库 |
| 通用 JSON/CSV | 用户提供的导出文件 | 知识库（用户指定格式映射） |

## 五、回滚

### 5.1 迁移回滚

如果迁移后程序运行异常：

1. 用户触发回滚（通过命令行参数或 UI）
2. 从 `backups/migration_{timestamp}/` 恢复所有文件
3. 恢复旧 `schema_version`
4. 验证恢复结果
5. 报告回滚完成

### 5.2 回滚限制

| 限制 | 说明 |
|------|------|
| 迁移后已产生新数据 | 回滚会覆盖新数据，需用户确认 |
| 备份已过期/删除 | 无法回滚，需手动修复 |
| 跨多版本迁移 | 只能逐级回滚，不能直接跳回 |

## 六、数据修复

当检测到数据损坏（JSON 解析失败、字段缺失）时：

1. 尝试自动修复（如从备份恢复、用默认值填充）
2. 自动修复失败 → 隔离损坏文件到 `corrupted/` 目录
3. 生成修复报告，提示用户手动处理

## 七、环境迁移（备份与恢复）

### 7.1 导出

AI_ASSISTANT_DATA/config/ \
AI_ASSISTANT_DATA/knowledge/ \
AI_ASSISTANT_DATA/memory/ \
AI_ASSISTANT_DATA/backups/
纯文本
### 7.2 导入

1. 解压到目标机器的 `AI_ASSISTANT_DATA/`
2. 运行迁移检查（确保格式兼容）
3. 如有版本差异，触发迁移流程

### 7.3 身份连续性

用户身份靠 `data/config/user-profile.json` 中的 `user_id`（UUID，首次启动时生成）。换电脑 / 重装后 UUID 不变 → Agent 认出是同一用户；偏好、沟通风格、命名审美等长期记忆随之迁移。迁移时**不清空 `user_id`**。

## 八、审计与日志

所有迁移操作记录到 `AI_ASSISTANT_DATA/logs/migration.log`：

| 事件 | 记录内容 |
|------|---------|
| 迁移开始 | 时间戳、源版本、目标版本、文件列表 |
| 单文件迁移 | 文件路径、操作类型、结果 |
| 迁移完成 | 成功/失败、耗时、迁移文件数 |
| 回滚 | 时间戳、回滚原因、恢复文件列表 |
