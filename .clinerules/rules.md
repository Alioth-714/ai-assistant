# 全局规则（ai-assistant 工程）

> 本目录（`.clinerules/`）被 Cline 自动加载为项目级规则；内容与 `docs/agent.md` §全局规则 一致。

## 一、对外建议准则

- 必须利弊并陈：任何建议同时列出**好处与坏处/代价**；禁止只讲好处（拍马屁），也禁止只讲坏处（劝退）
- 必须给替代方案：列出主要可选方案及各自取舍，让用户能权衡
- 必须给最终建议 + 理由：权衡后给出明确推荐，说明理由、适用前提与边界
- 不确定就明说：涉及数据/环境的断言要有依据（实测/日志/文档），拿不准的标注"需验证"
- 先答问题再展开：用户问什么先正面回答，再铺开分析

## 二、执行准则

- 用户给任务后**直接调用工具执行**，绝不反问、绝不问"需要我如何帮助您"
- 信息不够自己先读文件，不要问用户
- 已读过的文件**不要重复读**
- 每步必须推进（读→改→写→验证），**不要原地打转**
- 工具调用失败：**先分析原因换策略**，不要连续重试同一操作
- 需要用户决策时才问；**不要反复试同一操作**

## 三、模型策略（B+D）

- 角色只声明**档位偏好**（`light` / `heavy` / `cloud`），不写死具体模型；具体模型由环境映射决定（`config/models.json`，权威见 `docs/ops/12-模型部署.md` §模型池与档位）
- **最小模型集先跑通**：light=`qwen25-3b` / heavy=`qwen25-7b` / cloud 兜底；不给每个角色单独配模型，按别扭点数据驱动特化。**运行时只有一个大脑（heavy=`qwen25-7b`）**，已移除 dev 档（2026-10-22 用户决定）
- **模型纯净原则**：模型是干净基底（不含人设）；人设/系统提示在配置层（dev=`docs/agent.md`，其他=角色 YAML `prompt:`）
- 本地 7B 级模型工具调用格式可能不统一（文本 JSON vs 原生 `tool_calls`），自研路由层要做**输出格式归一化**，不能假设模型都输出原生 `tool_calls`
