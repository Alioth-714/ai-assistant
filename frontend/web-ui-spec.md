# Web 界面实现规格（供本地模型/Cline 使用）

> 用途：这是 **阶段 1a（UI 先行 MVP）** 的 Web 界面实现规格。把它作为 system/上下文交给本地模型（qwen25-7b + Cline），让它按本文档产出前端代码。
> 权威设计：`docs/design/24-前端交互设计.md`（本文档是其可执行摘要）。
> 版本：2026-01-15 | 状态：MVP 规格

---

## 0. 给执行模型的一句话

只做**前端（纯 HTML+CSS+JS）**，做成**可 mock 运行的聊天界面**：先能在浏览器里直接打开 `index.html` 聊天、切换 3 个角色、看到流式输出；后端接口按本文档第 9 节**定义好名字和参数**即可，先不接真实后端。不要做后端、不要做任务编排、不要做知识库 UI。

---

## 1. MVP 目标与范围

**目标**：一个能"聊天 + 切角色 + 流式输出"的桌面 Web 界面（Tauri 壳，先浏览器可跑）。

**MVP 做**：
- 布局：左侧边栏（角色选择）+ 主区域（对话历史 + 输入区）+ 底部状态栏
- 角色：3 个内置角色可切换（dev / general / custom-role），切换后对话上下文隔离
- 对话：用户/助手/系统/错误 4 类消息，助手消息流式输出（mock 逐字）
- 输入：多行输入，`Ctrl+Enter` 发送、`Shift+Enter` 换行，支持 `/role` `/clear` 命令
- 主题：明暗切换（CSS Variables）
- 状态栏：显示「模型加载状态 / 运行 Agent 数 / 待确认数」（mock 值）

**MVP 不做**（后续阶段再做，先留占位）：
- 真实后端调用、子 Agent 任务编排、任务卡片
- 权限确认弹窗（后续阶段 1b）
- 设置页、模型管理、知识库/记忆管理、日志查看
- 多模态/图片上传、云

---

## 2. 技术栈

| 项 | 选择 | 说明 |
|---|---|---|
| UI | 纯 HTML + CSS + JS | 无框架，直接操作 DOM |
| 桌面壳 | Tauri v1 | 后端 Rust（后续接），前端通过 `invoke` 调命令 |
| WebView | Windows WebView2 | 系统已装 |
| 样式 | CSS Variables | 明暗主题切换 |
| 通信 | Tauri `invoke` + `event` | 前端→后端 invoke；后端→前端 listen 事件 |
| 构建 | 无构建步骤 | 直接编辑 HTML/JS，刷新即生效 |

## 5. 组件规格

### 5.1 侧边栏
- **角色选择**：列出角色名 + 图标 + 描述，当前角色高亮；点击切换（见 §6）。
- **任务列表 / 设置**：MVP 显示占位文案「后续阶段」。

### 5.2 主区域
- **对话历史**：消息列表，自动滚动到底部。
- **输入区**：多行 `textarea`；`Ctrl+Enter` 发送；`Shift+Enter` 换行；空消息不可发送；发送中显示「停止」按钮。

### 5.3 状态栏
- 左侧：模型状态点（绿=就绪/灰=未加载，mock 为就绪）。
- 中间：运行 Agent 数（mock 0）。
- 右侧：待确认数（mock 0，闪烁样式预留）。

---

## 6. 角色管理

- MVP 内置 3 角色（数据在 `roles.js` 中定义，字段见下）：
  - **dev**（开发）：代码/文件/终端，主协调者 `qwen25-7b`
  - **general**（通用）：通用问答
  - **custom-role**（垂直/自定义）：示例垂直角色
- 角色数据结构：
  ```js
  { id: 'dev', name: '开发', desc: '代码/文件/终端', model: 'qwen25-7b', icon: '👨‍💻' }
  ```
- **切换逻辑**：切换角色 → 清空当前输入、对话历史按角色隔离（每个角色独立消息列表，切回来还在）；顶部或状态栏显示当前角色。
- **可扩展**：后续角色 = YAML 文件自动加载（第 11 节注），前端只渲染 `roles.js` 返回的列表，不写死。MVP 中把角色列表做成**一个数组**，方便以后动态加。

---

## 7. 交互流程

1. 用户输入 → 回车发送 → 消息以「用户消息」渲染。
2. 助手开始回复：显示「小明同学：正在分析...▌」（光标动画）。
3. mock 流式：`api.js` 用定时器逐字吐出预设回复（或简单回声），渲染为「助手消息」；结束后光标消失。
4. 流式进行中，发送按钮变为「停止」，点击停止中断。
5. `/clear` 清空当前角色对话；`/role 角色名` 快速切换（无参数则提示用法）。
6. 错误场景（mock）：输入包含 `error` 关键字时，渲染一条「错误/警告」消息。

---

## 8. 数据模型

消息对象：
```js
{ id: 'msg_001', role: 'user'|'assistant'|'system'|'error',
  content: '...', ts: 1700000000000 }
```
- 渲染规则：user 右对齐蓝色；assistant 左对齐灰底（支持简单 Markdown：**加粗**、`代码`、代码块）；system 居中浅黄；error 居中红/橙。
- 每个角色独立 `messages[]` 数组，存内存即可（MVP 不落盘）。

## 9. 与后端通信契约（先定义，MVP 用 mock）

### 9.1 api.js 双实现
```js
const USE_TAURI = false; // true 后走 Tauri invoke
// mock: sendMessage 返回 Promise<string>，用 setTimeout 分片逐字回调 onChunk
```
- `USE_TAURI=false`：浏览器直开可用（mock）。
- `USE_TAURI=true`：调用 Tauri 命令（后续后端按同名实现）。

### 9.2 Tauri 命令（invoke，后端待实现，签名先定好）
| 命令 | 参数 | 返回 |
|---|---|---|
| `send_message` | `{ content, role }` | 最终完整回复（流式另走事件） |
| `get_roles` | - | 角色数组 `[{id,name,desc,model,icon}]` |
| `switch_role` | `{ role }` | 新角色信息 |
| `stop_stream` | - | `{ ok: true }` |
| `get_status` | - | `{ routerModel, coordinatorModel, agents, pendingConfirm }` |

### 9.3 Tauri 事件（listen，后端 → 前端）
| 事件 | payload |
|---|---|
| `stream_chunk` | `{ text }` |
| `task_progress` | `{ taskId, status, detail }`（后续用） |
| `permission_request` | `{ requestId, op, target, level }`（后续用） |
| `role_changed` | `{ role }` |

> MVP 前端在 `USE_TAURI=false` 时不需要这些事件；但 `api.js` 里预留 `listen` 分支，注释说明后续启用。

## 10. 主题与快捷键

- 明暗主题：`<html data-theme="dark|light">` + CSS Variables（`--bg`、`--card`、`--text`、`--accent`、`--user-bg`、`--assistant-bg`、`--error` 等）。默认跟随系统或固定 light；右上角按钮切换，存 localStorage。
- 快捷键：`Ctrl+Enter` 发送；`Shift+Enter` 换行；`Ctrl+R` 循环切换角色。
- 基础可访问性：按钮有 `aria-label`，焦点可见，字体默认 14px 可调（MVP 至少给出 CSS 变量）。

---

## 11. 安全约束（MVP 前端层）

- 前端**不存储**任何密钥/敏感信息；API Key 一律显示 `****`（MVP 无此界面，仅遵守）。
- 所有输入经后端校验后再执行（MVP 无执行，仅展示）。
- 渲染用户/模型内容时，对文本做 HTML 转义，防止注入（**必做**：`content` 不得直接 `innerHTML`，需转义或白名单 Markdown 渲染）。
